# 🛤️ 오늘의 길 (TodayPath) 명세

> 목적: 아이가 고르지 않아도 매일 네 정거장(오늘 배운 것 → 내일 맛보기 → 다시 보기 → 돌림 칸)이 공부방 월드 맨 위에 자동으로 놓여, 인기 없는 과목·콘텐츠도 루틴처럼 지나가게 한다. 콘텐츠를 없애지 않고 「길」로 데려간다.
> 위험도: **L2**(공통 코어 `kids/core/` 새 모듈, 퀘스트·보상 완료 지점 연결) + **L1-화면**(로비 카드). 노션 스키마·쓰기 없음(읽기만). 교차 검토 필수(GEMINI.md §9).
> 작성: 2026-11-23 Claude Code. 근거: 코드 조사(§1), `docs/learning_record_spec.md`, `docs/study_usage_report_spec.md`. 설계 검토 반영본(§12).
> 상태: **설계 v2 승인(2026-11-23, §13) — 1차 구현 중.**

## 0. 원칙

1. **고르게 하지 않고 놓아 둔다.** 정거장은 추천일 뿐 순서를 강제하지 않는다. 다음에 갈 곳(완료 안 된 첫 정거장) 하나만 강조한다.
2. **하루 한 번 편성, 그날은 고정.** 노선은 KST 날짜 기준으로 기기에 고정한다. 하루 중에 정거장이 바뀌지 않게 한다(예외: §6-1 조회 실패 노선의 한 번 보정).
3. **완료는 이미 있는 신호로만.** 새 타이머·체류 판정을 만들지 않는다(1차). 레슨 완주·과목방 퀴즈 완주·사회 자료분석 완주·동화 완독·독해 완료·하루 체크인처럼 화면이 이미 「끝났다」고 아는 지점만 쓴다(§5).
4. **자연어를 해석하지 않는다**(§8-5). 과목은 **명시적인 과목 키 맵**(§2-1)과 정확히 같은 글자만 받는다. `includes`·정규식·괄호 자르기 금지. 맵 밖 글자(예 `영어(L9)`, `국어(용어방)`, `덧셈`, `공부`, `데일리 루틴`)는 버린다. 단원 목록은 `|`로만 나눈다.
5. **노션에 쓰지 않는다.** 학습일지는 읽기만(하루 한 번). 노선·완료 장부는 기기 `localStorage`에만.
6. **실패해도 카드는 뜬다.** 조회가 실패하거나 늦으면 대체 규칙으로 편성하고(§3-6), 카드가 로비를 막지 않는다.

## 2. 정거장

### 2-1. 과목 키 맵 (단일 원본)
```js
const SUBJECTS = { korean: '국어', math: '수학', english: '영어', society: '사회', science: '과학', haru: '하루' };
// 한글 → 키는 이 표를 뒤집은 것. 정확히 같은 글자만. 키를 받아도 됨.
```
- 아이별 후보 `eligible` = `USER_CONFIGS[아이].subjects`(민서는 여기서 이미 사회·과학 없음). 이 밖(도덕·미술·보건·용어사전)은 정거장에 오지 않는다.
- **교과 후보** = `eligible` − {하루}. 1·2번은 교과 후보에서만, 하루는 4번에만 온다.
- **어휘 과목** = 국어·영어·사회·과학(3·3·3 레슨이 되는 교과. `QuestMastery.SUBJECT_KO`에는 도덕·미술·보건도 있으나 아이 후보에 없음).

### 2-2. 네 정거장

| # | 이름 | 과목 | 데려갈 곳 (`?user=<키>&tp=<번호>`를 붙여 조립) | 완료 (§5) |
| :---: | :--- | :--- | :--- | :--- |
| 1 | 🎒 오늘 배운 것 | 오늘 시간표 교과 1개. 주말·시간표 없는 날은 **가장 최근 등교일**(금요일) 과목, 이름 「이번 주 배운 것」 | 어휘 과목: `quest_runner.html?subject=<키>` (민수 3단계 레슨, 민서 `&lesson=bite`) · 수학: `quest_runner.html?subject=math`(기존 4+1). **`unit`은 넣지 않음**(러너가 부모 진도 단원을 씀) | 그 과목 **레슨 완주** |
| 2 | 🔭 내일 맛보기 | 다음 등교일 시간표 교과 1개(1번과 다름) | 그 과목방(`SUBJECT_META.href`) — 1단계 동화 도서관·2단계 용어가 있는 곳 | 그 과목 **동화 완독·독해 완료·과목방 퀴즈 완주·레슨 완주** 중 하나 |
| 3 | 🔁 다시 보기 | §3-4 대체 순서 | §3-4 | `tp=3`으로 열린 화면에서 **레슨 완주·퀴즈 완주** |
| 4 | 🎡 돌림 칸 | 최근 7일 가장 덜 간 과목(1·2번과 다름, 하루 포함) | 그 과목방(하루는 하루방) | 하루면 **오늘 체크인**, 아니면 그 과목 아무 완료 신호. 체류 30~45초 판정은 2차 |

- 1·2·4번 과목은 서로 다르다. 3번은 겹쳐도 된다(복습). 그래서 **`tp`가 붙은 화면의 완료는 그 정거장에만** 귀속한다(§5-1).
- 카드에 정거장마다: 번호·이모지·이름·과목·한 줄 설명(예 「어제 헷갈린 낱말: minute · lunch · sleep」), 완료면 ✅.

## 3. 편성 (순수 함수 `TodayPath.plan`)

```js
TodayPath.plan({
  child: '민수' | '민서', childKey: 'minsu' | 'minseo',
  now: Date.now(),                         // KST 날짜·요일은 이것으로만 계산
  timetable: { [dayName]: ['국어', ...] },  // §4-1, 교과 한글(맵 통과분)
  eligible: ['english','korean',...],       // USER_CONFIGS 과목 키
  history: null | { visits: { korean: ['2026-11-20', ...] }, logs: [{ date, subject, items }] },  // §4-2
  voca: [...]                               // 이 아이 VOCA 캐시 레코드(없으면 [])
}) → { v: 1, date: 'YYYY-MM-DD', provisional: boolean, stops: [Stop ×4] }
// Stop = { n, kind: 'today'|'tomorrow'|'review'|'rotate', subject: '<키>', title, detail, href, source }
```

### 3-1. 날짜·요일 (KST)
- `kstDate(now)`: `now + 9h`의 UTC 연월일을 직접 조립(`toISOString().slice` 금지 규칙 §8-5). 요일 = `now + 9h`의 UTC 요일. **기기 시간대와 무관**.
- 오늘 시간표 요일: 월~금이면 그날, 토·일이면 금요일(「이번 주 배운 것」).
- 다음 등교일: 월~목 → 다음 날, 금·토·일 → 월요일. 공휴일·방학은 모름(방학 모드 2차).
- 날짜 일련번호 `dayIndex` = KST 날짜의 1970-01-01부터 날 수(회전용).

### 3-2. 순위 (공통 비교)
과목 목록을 줄 세우는 규칙 하나로 1·2·4번을 모두 정한다:
1. 최근 7일 방문 일수 적은 순, 2. 마지막 방문이 오래된 순(안 간 과목이 맨 앞), 3. **기준 순서** — 시간표에서 온 후보는 시간표 순서, `eligible`에서 온 후보는 `eligible`을 `dayIndex % 길이`만큼 돌린 순서(날마다 다름).
- `history = null`이면 1·2를 건너뛰고 3만.

### 3-3. 1·2번 과목 짝
1. `T` = 오늘(또는 금요일) 과목 ∩ 교과 후보. **`T`가 비면 먼저** 교과 후보 중 어휘 과목을 순위로 채운다(1개).
2. `M` = 다음 등교일 과목 ∩ 교과 후보.
3. `T`·`M`을 각각 순위로 줄 세우고, (1번 순위, 2번 순위) 순으로 훑어 **서로 다른 첫 짝**. → 민서 수(국·수)→목(국)이어도 1번 수학·2번 국어로 맞춰진다.
4. 짝이 없으면(`M`이 비었거나 `M` = {1번}) 2번은 교과 후보 − {1번} 순위 1위, 설명 「골고루 한 과목 맛보기」(민서 화요일처럼 다음 날 교과가 없을 때도).

### 3-4. 3번 「다시 보기」 대체 순서
**① 최근 오답** (`history`가 있을 때)
- 후보 문항: `history.logs`의 `v:`·`c:` 키 중 `틀림 ≥ 1`이고, 아래 과목 확인을 통과한 것. `r:`·`s:`·`g:`는 그 문항으로 바로 데려갈 길이 없어 1차에서 뺀다.
  - `v:` → 캐시 레코드 중 `id`(하이픈 뺀 소문자 32자)가 같은 것. 그 레코드 `subject` 배열의 맵 값 중 어휘 과목·`eligible`인 첫 값. 단원 = 레코드 `stage`를 `|`로 나눈 첫 토막. **그 아이 캐시 레코드 중 같은 과목·같은 단원 토막을 가진 항목이 3개 이상**일 때만(3개 미만이면 러너가 정적 문제로 바뀜). 못 찾으면 버림.
  - `c:` → 그 일지 행 `과목`이 정확히 `사회`이고 `eligible`에 사회가 있을 때만(과학 실험 퀴즈는 진입 버튼이 없어 1차 제외).
- 날짜: 후보 문항이 **하나라도 있는 가장 최근 날**(오늘 이전 7일). 그날 후보만 쓴다.
- 정렬: 틀림 내림차순 → 시도 내림차순 → 키 글자순. 맨 위 문항의 과목을 3번 과목으로, 그 과목 후보 최대 3개.
- 데려갈 곳: `v:` → `quest_runner.html?subject=<키>&unit=<맨 위 v: 문항의 단원 토막>`(민서 `&lesson=bite`), 설명 낱말(`word`) 최대 3개 「 · 」. `c:` → 사회방, 설명 「어제 헷갈린 자료 N개」(자료분석 완주로 완료, §5-2).
- ⚠️ 1차는 **그 단원 레슨**으로 데려갈 뿐, 틀린 3문항만 골라 내지는 않는다(3·3·3 출제 규칙 그대로). 「그 문항만」은 2차(§9).

**② 녹슨 왕관·은메달** (민수만 — 한입 레슨은 왕관을 내지 않음)
- 캐시에서 이 아이 레코드(`target`에 아이 이름 또는 `공통`, 또는 `target` 비어 있음 — `selectUnitItems`와 같은 조건), 어휘 과목·`eligible`. 숙련도는 `remoteStateOf`와 같은 해석(`isAchieved`면 금메달) 후 `isRusty(오늘)` 또는 `isLv3Eligible(오늘)`.
- (과목, 단원 토막)별로 모아, 항목 3개 이상인 묶음 중 대상 수 많은 순 → 녹슨 왕관 많은 순 → `과목키::단원` 글자순. 그 단원 3단계 레슨(보스 단계가 왕관을 맨 앞에 냄). 설명 「녹슨 왕관 N개 닦기」/「은메달 N개 금메달 도전」.
- 알려진 한계: 그날 기기에서 막 오른 숙련도(`MINMIN_QUEST_MASTERY_V1_`)는 반영하지 않는다(노선은 그날 첫 로비에서 정해지고, 전날 진도는 노션→캐시에 이미 있음).

**③ 최근 단원 가벼운 복습**
- 최근 7일 가장 최근에 간 어휘 과목(없으면 1번이 어휘 과목이면 그것, 아니면 교과 후보 중 어휘 과목 순위 1위). 그 과목 레슨, **`unit` 없이**(부모 진도 단원). 설명 「지난 단원 한 번 더」.
- 어휘 과목이 하나도 없으면 1번 데려갈 곳을 그대로(`tp=3`).

### 3-5. 4번 「돌림 칸」
- 후보 = `eligible` − {1번, 2번}(하루 포함). §3-2 순위 1위.
- 민서는 `eligible`에 사회·과학이 없어 자동으로 국·수·영·하루 안에서만 돈다(별도 분기 없음 — 시험으로 확인).

### 3-6. 기록이 없을 때 (`history = null`)
- 1·2·4번: 기준 순서만. 3번: ① 건너뛰고 ②→③.
- 이 노선은 `provisional: true`(§6-1). VOCA 캐시만 비었을 때는 `provisional`로 치지 않고, 3번만 나중에 다시 고를 재료(`reviewPending`)를 남긴다(§6-1).

## 4. 입력 모으기 (로비 쪽 `lobby_today_path.js`)

### 4-1. 시간표 → §13 결정 1
- `timetable-boost.js`에 순수 도우미 `getSubjectsForDay(childName, dayName)` → 그 요일 교과 한글 배열:
  1. `MINMIN_TIMETABLE_CACHE_V11`의 `staticRows`에서 `child === 이름` · `dayOfWeek === 요일` · `subject`가 맵의 교과 한글과 **정확히 같은** 행, 교시 순, 중복 없이.
  2. 캐시가 없거나 캐시에 **그 학생 행이 하나도 없으면** 코드 안 기본 시간표. 학생 행은 있는데 그날 교과가 없으면 빈 배열(§13 결정 2 — 등록 시간표 기준, 빈 날은 순위로 고르게).
- `overlayRows`(날짜별 행사)는 1차에서 보지 않는다.
- 플래너에는 오늘·다음 등교일·금요일 세 요일만 담은 `timetable`을 넘긴다.

### 4-2. 학습일지 읽기 (하루 한 번)
- `POST {Worker}/v1/databases/{STUDY_LOG_DB}/query`, 필터 `학생 = <아이>` AND `입장 ≥ 오늘−8일`, **`sorts: 입장 내림차순`**(쪽 경계 누락 방지, 2026-11-17 확인된 노션 동작), `page_size 100`, 최대 5쪽, 쪽은 차례로. `?force=true` 없이. **전체 예산 6초** — 넘기거나 어느 쪽이라도 실패하면 받은 것을 버리고 `history = null`(부분 자료로 하루를 고정하지 않음). 5쪽 상한에 닿으면 받은 만큼 쓴다(최신순이라 잘리는 것은 오래된 쪽).
- KST 날짜(`입장`)로 **오늘 이전 7일**만(오늘은 빼서 하루 중 순위가 흔들리지 않게).
- 측정 행(`ID`가 `학습활동_`로 시작하거나 `활동측정`이 있음): `과목`이 맵 한글과 정확히 같으면 `visits[키]`에 그 날짜(중복 없이).
- 일지 행(그 밖): `문항기록`이 있으면 `LearningLog.decode` → `null`이면 건너뜀. `logs`에 `{ date, subject: 과목칸 원문, items }`.
- 행 나누기는 리포트(`study_usage_report.mjs` §2-0)와 같은 규칙. 시험에서 같은 표본으로 대조.

### 4-3. VOCA 캐시
- `_loadVocaFromCache('ALL', VOCA_DB_ID)`(없으면 `_loadVocaFromCache(아이 이름, VOCA_DB_ID)`) → 이 아이 레코드만(§3-4 ② 조건).
- 매일 첫 진입은 캐시가 비어 있으므로, 로비가 이미 부르는 `prefetchVocaData(realName)`의 Promise를 `window.__lobbyVocaPrefetch`로 남기고(`lobby_controller.js` 한 줄), 편성은 **학습일지 조회와 이 Promise를 함께 기다린다**(같은 6초 예산 안). 끝까지 비면 `[]`.
- 숙련도 판정 함수 3개(`parseMastery`·`isRusty`·`isLv3Eligible`)와 `isAchieved` 보정은 **`today-path.js`에 같은 규칙으로 두고(약 15줄)**, 시험이 실제 `quest-mastery.js`(`module.exports`)와 경계값을 1:1 대조한다(`study_usage_report`의 `decode`와 같은 방식). 로비에 792줄을 싣지 않는다.

### 4-4. 싣기·순서
- `lobby.html`에 `<script src="./kids/core/today-path.js?v=<버전>">`와 `<script src="./kids/js/lobby_today_path.js?v=<버전>">`를 **`lobby_config.js` 태그 앞**에 둔다(`lobby-split` 시험의 세 태그 연속 규칙 유지). `notion-helper.js` 자동 로더 목록에도 **같은 `today-path.js?v=<버전>` 문자열**로 넣어 로비에서는 중복 검사로 건너뛰게 한다(버전 문자열 일치를 시험이 확인).
- `mount(userKey)`는 여러 번 불려도 된다: 부를 때마다 번호표(`token`)를 올리고, 늦게 온 이전 결과는 버린다. 같은 아이 조회는 진행 중인 Promise 하나를 같이 쓴다.
- 오늘 노선이 이미 저장돼 있으면 코어 로드를 기다리지 않고 바로 그린다. 새로 편성할 때만 `window.LearningLog`·`window._loadVocaFromCache`가 실릴 때까지 기다린다(같은 예산 안, 없으면 그 재료만 빈 값).

## 5. 완료 신호

### 5-1. 완료 장부 (기기)
- 키 `MINMIN_TODAY_PATH_DONE_V1_<아이 이름>` = `{ "date": "YYYY-MM-DD", "s": { "<과목 키>": ["lesson","quiz","story","reading"] }, "tp": [3] }`. 날짜가 바뀌면 통째로 새로 시작.
- 쓰기 `TodayPath.markDone({ child?, subject, kind })`:
  - **먼저** `currentUserName`이 아빠·엄마·어른이면 기록하지 않는다(`child`를 넘겨도). 그다음 `child`(이름 또는 키), 없으면 `currentChild`/`currentUser`.
  - `subject`는 맵 키 또는 맵 한글과 정확히 같을 때만. `kind` ∈ `lesson|quiz|story|reading`.
  - 현재 URL에 `tp=1~4`가 있으면 **`tp`에만** 더하고 `s`에는 넣지 않는다(3번으로 들어가 푼 영어 레슨이 1번 영어까지 켜지지 않게). 없으면 `s[과목]`에만.

- 판정 `TodayPath.doneState(route, ledger, haruDone)` → `[bool ×4]` 순수 함수:

## 6. 저장

### 6-1. 노선 고정
- 키 `MINMIN_TODAY_PATH_V1_<아이 이름>` = `plan()` 결과. `date`가 오늘(KST)이면 그대로, 아니면 새로 편성.
- **조회 실패 노선 한 번 보정**: `provisional: true`(학습일지 조회 실패)이고 **완료된 정거장이 없으면**, 그날 다음 로비 열림에서 조회를 한 번 더 해 성공하면 다시 편성. 하나라도 완료했으면 그대로(아이가 따라가는 길을 바꾸지 않음). 보정 시도는 하루 한 번(`retried: true`).
- 부모 시뮬레이터: 노선을 보여 주되 새로 저장하지 않는다(아이 기기 노선을 바꾸지 않게).
- **3번만 늦게 다시 고르기**(`reviewPending`, 구현 중 화면 확인으로 추가): 매일 첫 진입은 어휘 캐시(약 2,300행, 약 15초)가 6초 예산보다 늦는다. 편성 때 캐시가 비었고 학습일지 조회는 됐으며 3번이 오답으로 정해지지 않았고, (최근 `v:` 오답이 있거나 민수 — 녹슨 왕관·은메달)이면 노선에 3번 재료(방문·`v:`/`c:` 오답 요약)를 남긴다. 로비는 캐시 Promise(`__lobbyVocaPrefetch`)가 끝나면 **3번을 아직 안 했을 때만** 3번 하나를 다시 골라 저장·그린다(1·2·4번 그대로). 한 번 바꾸면 재료를 지운다.
- `pageshow`(뒤로 가기로 로비 복귀): 화면 노선의 `date`가 오늘이 아니면 `mount`를 다시 하고, 같으면 완료 상태만 다시 읽는다.

### 15-1. 4번 체류 판정
- **왜 측정기 상태(`getStatus`)를 그대로 못 쓰나**: 측정기는 과목방 첫 화면(미션 창을 열기 전)과 수학방(`math.html`)·도서관 경로를 활동으로 치지 않는다(`pageContext` = `null` → `eligible` 거짓, 터치해도 `lastAction` 안 바뀜, `study-activity.js:88-90`). 4번은 「둘러보기라도 들어가 보기」가 목적이라 첫 화면도 세야 한다.
- **그래서 측정기와 같은 규칙을 직접 쓴다**(새 활동 모델을 만들지 않음): 화면이 보이고(`visibilityState === 'visible'`) **최근 `StudyActivity.IDLE_MS`(90초) 안에 실제 입력**(`pointerdown`·`keydown`·`touchstart`·`wheel`, `isTrusted` — 측정기와 같은 종류)이 있으면 1초. 처음 입력 전에는 쌓이지 않는다(= 「실제로 한 번 이상 터치」). 화면을 떠나면(숨김) 입력 임대가 끝난다.
- 지켜보는 조건: 부모 시뮬레이터 아님, 오늘 노선이 있고 4번 미완료, URL에 `tp=1~3`이 **없음**(1·2·3번 화면의 시간이 4번으로 새지 않게), 화면 과목이 4번 과목 — `tp=4`면 노선의 4번 과목, 아니면 `window.currentSubject`(과목방이 맵과 같은 글자로 둠) 또는 `StudyActivity.pageContext(window).subject`를 맵으로 바꾼 값(하루방·동화·퀘스트 러너).
- 쌓인 초는 장부 `dwell: { <과목 키>: 초 }`에 **매초** 저장(작은 JSON, 페이지를 떠나도 잃지 않게) → **같은 과목의 하위 페이지를 옮겨 다녀도 이어진다**. 대상 판정과 기록은 같은 시각 하나로(자정 경계). 30초가 되면 `markDone({ subject: <4번 과목>, kind: 'visit' })`(URL `tp=4`면 `tp`에, 아니면 `s`에) 한 번.
- `kind`에 `visit` 추가. `visit`는 **4번 판정에만**: 1번 `lesson`만, 2번 `lesson·quiz·story·reading`만, 4번은 아무거나. 4번이 하루면 `haruDone || s.haru` 아무거나.
- 알려진 한계: 과학 가상실험실 15개 화면은 `study-activity.js`만 싣고 `today-path.js`를 싣지 않아 체류가 안 쌓인다(과학방 첫 화면·실험 퀴즈는 쌓임). 1초 간격 `setInterval` 하나가 `today-path.js`가 실린 화면마다 돌지만, 최근 입력이 없으면 바로 끝나고 대상 화면이 아니면 노선·장부만 읽고 끝난다. 같은 과목 탭 두 개를 동시에 띄우면 두 배로 쌓인다(드묾).

### 15-2. 네 정거장 완주 보너스 +3 (하루 한 번)
- 로비가 카드를 그릴 때 넷 다 완료 + 장부에 `bonus` 없음 + 부모 시뮬레이터 아님이면:

  2. 보상 모듈 `window.MinminRewardGrant`(`notion-study-logger.js`가 싣는 `reward-grant.js`)를 최대 10초 기다린다. 없으면 이번엔 건너뜀(장부에 안 씀 → 다음 로비에서 다시).
  3. 기다린 뒤 장부를 **다시 읽어** `bonus`가 없고 화면 아이가 그대로일 때만, `bonus: true`를 **먼저 저장**하고 `MinminRewardGrant.grant(3, false, null, { childName, currentTheme, subject })`.

- 카드 제목 옆 「🎉 오늘의 길 완주! +3」.
- 알려진 한계: 1번 과목이 그날 보상 한도에 이미 닿았으면 엔진이 0개를 주고 「다 모았어요」 알림(엔진 동작 그대로). 로비 상단 보석 숫자는 다음 로비 열림 때 갱신. 장부가 기기별이라 두 기기에서 각각 넷 다 하면 기기마다 한 번.

### 15-3. 방학 모드
- 설정 모달(`fairy-settings-engine.js`, 로비 ⚙️)에 「🏖️ 방학 모드(부모님과 정해요)」 켜기/끄기. 값은 `appSettings.vacation_mode`(학습설정 JSON 조각 저장 그대로, 스키마 변경 없음).
- **로비는 아이 전용 키에서 직접 읽는다**: `MINMIN_APP_SETTINGS_<son|daughter>`의 `vacation_mode === true`. (공용 레거시 키로 폴백하지 않음 — 다른 아이 값이 번지지 않게. 설정 엔진이 늦게 실려도 첫 그리기부터 정확.)
- 켜면 편성에서 시간표를 보지 않는다: 1번 = 교과 후보 순위 1위 「방학 공부」, 2번 = 나머지 순위 1위 「골고루 한 과목 맛보기」. 3·4번 같음. 노선에 `vacation: true`.
- 저장된 노선의 `Boolean(vacation)`이 지금 설정과 다르면 그날이라도 다시 편성한다(부모가 일부러 바꾼 것): 이전 노선을 「보정 대상」으로 넘기지 않고(조회 실패해도 새 설정으로 편성), 장부의 `tp`(옛 정거장 번호 완료)는 지운다(과목별 완료 `s`·체류는 그대로).
- 설정이 바뀌면 로비 카드를 바로 다시 그린다: `onSettingChanged('vacation_mode')`와, 클라우드에서 받은 값이 달라졌을 때(`syncFromCloud`) 같은 알림 → `window.LobbyTodayPath?.mount(window.__activeLobbyUser)`(로비가 아니면 아무 일 없음).
- **설정 저장 안전 보강**(이 토글이 노션 저장을 부르므로): `saveToCloud`가 기기에 그 아이 학습설정 캐시(`MINMIN_CLOUD_SETTINGS_<이름>`)가 없으면 **노션 페이지의 `학습설정`을 먼저 읽어 바탕으로 삼는다**(지금은 `{appSettings}`만 보내 진도 설정·저금통·퀴즈 흐름이 지워질 수 있음). 부모 판정에 `어른` 추가.
- 보상 버프(🔥 오늘 복습)는 방학 모드와 무관(범위 밖).
- 알려진 한계: 부모 시뮬레이터(아빠·엄마·어른)에서 바꾸면 기존 규칙대로 그 기기에만 저장. 학습설정 캐시 아이 섞임(`quiz-flow-controller.js`가 늦게 실린 이름 함수로 키를 정함, `syncFromCloud`가 학생을 받지 않음)은 기존 결함 → 현황판 카드.

### 15-4. 「틀린 문항만」 먼저 출제
- 3번이 `v:` 오답이면 링크에 `focus=<id|id|id>`: `v:`를 뗀 32자, **맨 위 문항과 같은 단원** 것만(다른 단원 낱말은 그 레슨에 안 나오므로 설명에도 넣지 않음), 최대 3개, 틀림 순.
- 민수(3단계 레슨)는 단원 항목 **5개 이상**일 때만 그 단원으로 데려간다(3~4개면 레슨이 기존 5문제 판으로 바뀌어 focus가 안 먹음, `quest-lesson.js:84-92`). 민서(한입)는 3개 이상.
- `quest-runner.js`가 `focus`를 `|`로 나눠 `^[0-9a-f]{32}$`만, 중복 없이 → `QuestLessonUI.start({ …, focus })` → **첫 레슨에서만** `buildLesson({ …, focus })`.
- `buildLesson`: `focus` 순서대로 `pool`에서 찾은 항목(`focusItems`)을 앞에 둔다. 한입: 3문항 앞자리. 3단계: 워밍업 앞자리(`min(2, levelOf)`), **`focusItems`가 1개 이상일 때만** 그 레슨의 짝 맞추기 자리를 쓰지 않는다. 빌드업·보스 평소대로. 크레딧 규칙 그대로(`credit`이 `seen`에 넣어 뒤에서 다시 나오면 `noCredit`).
- 녹슨 왕관 항목은 `pool`에 없어 focus로도 안 나온다(한입 레슨 규칙 그대로).

### 15-5. 로비가 시간표를 하루 한 번 받아 오기
