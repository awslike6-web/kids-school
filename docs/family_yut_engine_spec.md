## 3. 판

```
10   9   8   7   6   5
11  26              21   4
12      27      22       3
            23
13      24      28       2
14  25              29   1
15  16  17  18  19  20
```

그림은 칸 위치를 보여 준다. **칸 연결은 아래 목록과 표가 기준이다.**
- **바깥길**: `1 → 2 → … → 19 → 20`. `20`이 참먹이(출발 겸 도착 모서리). 모서리는 `5`, `10`, `15`, `20`.
- **지름길 A**: `5 → 21 → 22 → 23 → 24 → 25 → 15`
- **지름길 B**: `10 → 26 → 27 → 23 → 28 → 29 → 20`
- `23`은 방(가운데). 판의 칸은 모두 29개다.
- 말 위치 값: `-1` 대기(`WAITING`), `1~29` 판 위, `30` 완주(`DONE`).

### 전진 경로 규칙
경로는 **이번 이동을 출발한 칸**으로 정한다. 지나가는 칸에서는 길을 바꾸지 않는다. 선택지는 없다.

| 출발 칸 | 그 뒤로 이어지는 칸 |
| :--- | :--- |
| `-1` | `1, 2, … , 20, 30` |
| `5` | `21, 22, 23, 24, 25, 15, 16, … , 20, 30` |
| `10` | `26, 27, 23, 28, 29, 20, 30` |
| `23` | `28, 29, 20, 30` |
| `21`, `22`, `24`, `25` | 지름길 A를 따라 이어서 `15, 16, … , 20, 30` |
| `26`, `27` | 지름길 B를 따라 이어서 `23, 28, 29, 20, 30` |
| `28`, `29` | `… , 20, 30` |
| 그 밖의 바깥길(`15`, `20` 포함) | 번호 순서로 `… , 20, 30` |

- 경로는 `30`에서 끝난다. 칸 수가 남아도 `30`까지만이다.
- **참먹이**: `20`에 딱 멈추면 아직 완주가 아니다. `20`에서 전진하면 무엇이든 완주다. `20`을 지나면 바로 완주다.
- 예: `routeOf(3,3) = [4,5,6]`(5를 지나가므로 바깥길), `routeOf(5,3) = [21,22,23]`, `routeOf(22,3) = [23,24,25]`, `routeOf(23,3) = [28,29,20]`, `routeOf(27,4) = [23,28,29,20]`, `routeOf(19,2) = [20,30]`, `routeOf(19,5) = [20,30]`.

## 4. 규칙

### 4-1. 던지기
| 결과 | 이름 | 칸 수 | 윷가락 |
| :--- | :--- | :--- | :--- |
| `backdo` | 빽도 | 뒤로 1 | 표시 가락(`sticks[0]`) 하나만 평평 |
| `do` | 도 | 1 | 표시 없는 가락 하나만 평평 |
| `gae` | 개 | 2 | 둘 평평 |
| `geol` | 걸 | 3 | 셋 평평 |
| `yut` | 윷 | 4 | 넷 평평 |
| `mo` | 모 | 5 | 평평한 것 없음 |

- 윷·모가 나오면 이어서 또 던진다. 결과는 `pending`에 쌓는다.
- 윷·모가 아닌 결과가 나오면 이동 단계로 간다.

### 4-2. 이동
- `pending`의 결과를 **어떤 순서로든** 하나씩 골라 쓴다. 쓴 결과는 지우고 뒤의 번호를 당긴다.
- 대기 말은 전진으로 판에 들어온다. 대기 말에는 빽도를 쓸 수 없다. 완주한 말은 움직일 수 없다.
- **업기**: 같은 칸의 같은 주인 말은 묶음이다. 그중 아무 말이나 지정해도 묶음 전체가 함께 움직인다. 대기 말은 묶음이 아니며, 지정한 말 하나만 나간다.
- **합류**: 이동을 마친 칸에 자기 말이 있으면 업는다. 추가 던지기는 없다.
- **잡기**: 이동을 마친 칸에 상대 말이 있으면 그 칸의 상대 말 전부를 대기(`-1`)로 보낸다. 지나가는 칸의 말은 영향이 없다. 빽도로 내려앉아도 잡는다.
- **잡으면 한 번 더**: 잡으면 차례를 유지하고 곧바로 던지기 단계로 간다. `pending`에 결과가 남아 있어도 먼저 던지고, 새 결과를 더해 함께 쓴다.
- 완주와 합류로는 추가 던지기가 없다.

### 4-3. 빽도와 지나온 길 (`trail`)
빽도는 **온 길을 되돌아간다.** 말마다 `trail`(지금 칸에 오기 전에 거친 칸 목록, 오래된 순)을 둔다.
- **전진**: `trail`에 출발 칸(판 위였을 때만)과 경로의 마지막을 뺀 칸들을 순서대로 덧붙인다.
- **빽도**: `trail`의 마지막 칸으로 가고 그 칸을 `trail`에서 뺀다.
- **`trail`이 비어 있을 때의 빽도**: `1`이면 `20`으로, 그 밖에는 번호 하나 앞(`n-1`)으로 간다. `trail`은 빈 채로 둔다.
- 대기로 돌아가거나 완주하면 `trail`은 빈 배열이다.
- 합류하면 **그 칸의 모든 말(먼저 있던 말 포함)이 움직인 말의 `trail`을 함께 쓴다.** 예: 바깥길로 `15`에 있던 말에 `25`에서 온 말이 업히면, 다음 빽도에서 둘 다 `25`로 간다.
- 예: 대기 말이 개로 `2`에 오면 `trail=[1]`. 빽도로 `1`, `trail=[]`. 또 빽도로 `20`, `trail=[]`. 이 말은 다음 전진에서 완주한다. 그 대신 또 빽도면 `19`.

### 4-4. 차례 넘김과 승리
- 이동 뒤 `pending`이 비었거나, 남은 결과를 쓸 수 있는 말이 하나도 없으면 남은 결과를 버리고 다음 사람에게 넘긴다. 쓸 수 없는 경우는 판 위에 말이 없고 남은 결과가 빽도뿐일 때다.
- 던진 뒤에도 같다. 판 위에 말이 없고 `pending`이 빽도뿐이면 버리고 넘긴다. `['yut','backdo']`처럼 윷으로 말을 올린 뒤 빽도를 쓸 수 있으면 버리지 않는다.
- 차례는 `players` 순서대로 돌고 마지막 다음은 처음이다.
- 잡은 직후에는 위 규칙을 적용하지 않는다(무조건 던지기 단계).
- **승리**: 한 사람의 말이 모두 완주하면 즉시 끝난다. `result={type:'win',winner:id}`, `pending=[]`, `phase='over'`, `turnPlayer`는 이긴 사람 그대로다. 그 뒤의 던지기·이동은 무효다.

## 5. D (데이터)
```json
{ "v": 1, "gameType": "yut", "stateVersion": 0, "turnPlayer": 0,
  "players": [ { "id": "p1", "name": "민서", "avatar": { "type": "emoji", "value": "🐰" }, "assist": "helper" } ],
  "publicBoard": {
    "pieceCount": 4, "phase": "throw", "pending": [], "log": [],
    "pieces": [ { "id": "p1-0", "owner": "p1", "pos": -1, "trail": [] } ] },
  "result": null, "lastAction": null }
```
- `pieces`는 `players` 순서, 사람 안에서는 번호 순서다. 말 id는 `{사람id}-{0부터}`. 이 순서는 게임 내내 바뀌지 않는다.
- `phase`: `throw`, `move`, `over`.
- `log`: 시작부터의 모든 행동. `{type:'THROW',by,result}` 또는 `{type:'MOVE',by,pieceId,throwIndex}`(`pieceId`는 호출에 넘긴 값).
- `lastAction`: `{type:'THROW',by,result}`, `{type:'MOVE',by,pieceIds,from,to,result,captured}`, `{type:'REMATCH'}`, 처음에는 `null`. `pieceIds`는 함께 움직인 말(`pieces` 순서), `captured`는 잡힌 말 id 배열.
- 상태를 바꾸는 함수는 새 상태를 돌려주고 `stateVersion`을 1 올린다(원본 불변, 오목과 같음). **무효 행동은 같은 객체를 그대로 돌려준다.**

## 6. API (`YutEngine`)
| 이름 | 설명 |
| :--- | :--- |
| `THROWS` | `['backdo','do','gae','geol','yut','mo']` |
| `STEPS` | `{backdo:-1,do:1,gae:2,geol:3,yut:4,mo:5}` |
| `WAITING`, `DONE` | `-1`, `30` |
| `routeOf(from, steps)` | §3의 전진 경로. `steps`는 1~5 정수, `from`은 `-1` 또는 `1~29` 정수. 그 밖은 `[]` |
| `rollSticks(rng=Math.random)` | `rng`를 정확히 4번 부른다. `sticks[i] = rng() < 0.5`(`true`가 평평). `{sticks, result}` 반환. 상태를 바꾸지 않는다 |
| `createGame(players, pieceCount=4)` | 2~4명, 말 2~4개. 잘못되면 예외. 사람 검사: `id`는 `/^[a-zA-Z0-9_-]{1,32}$/`·서로 다름, `name`은 앞뒤 공백을 뺀 1~8자(`Array.from` 기준), `avatar`는 객체이고 `JSON.stringify` 값이 서로 다름, `assist`는 `helper`/`tactic`/`classic`. 상태에는 `{id,name,avatar,assist}`만 복사해 넣는다 |
| `legalMoves(state)` | `move` 단계에서 지금 사람이 할 수 있는 이동 목록, 그 밖에는 `[]`. 항목: `{pieceIds,from,to,path,throwIndex,result,captures,joins}` |
| `applyThrow(state, result)` | `throw` 단계·승부 전·올바른 결과 이름일 때만 |
| `applyMove(state, pieceId, throwIndex)` | `move` 단계·승부 전·지금 사람의 말·`throwIndex`가 정수이고 범위 안·그 결과로 그 말이 움직일 수 있을 때만 |
| `rematch(state)` | 승부가 난 뒤에만(아니면 같은 상태). 첫 사람을 맨 뒤로 보낸 순서로 새 판. 말 개수 유지, `stateVersion`은 이전 값 +1, `lastAction={type:'REMATCH'}` |
| `isValidSaved(state)` | 아래 |

**`legalMoves` 세부**
- `throwIndex`마다, 지금 사람의 **칸별 묶음 하나당 항목 하나**를 만든다. 대기 말은 전부 합쳐 항목 하나이고, `pieceIds`는 가장 앞 번호의 대기 말 하나다. 판 위 묶음의 `pieceIds`는 그 칸의 내 말 전부(`pieces` 순서)다.
- 같은 결과가 `pending`에 둘 있어도 `throwIndex`별로 따로 만든다.
- `path`: 전진은 `routeOf` 결과, 빽도는 `[도착 칸]`. `to`: `path`의 마지막.
- `captures`: 잡힐 상대 말 id, `joins`: 합류할 내 말 id(움직이는 묶음 제외). `to`가 `30`이면 둘 다 빈 배열.

**`isValidSaved(state)`**: 예외 없이 `true`/`false`만 돌려준다. JSON 왕복 뒤의 상태를 받는다.
- `v`, `gameType`, `stateVersion`(0 이상 정수, `log` 길이 이상)을 검사한다.
- `createGame`으로 새 판을 만든 뒤 `log`를 처음부터 재생한다. 각 행동의 `by`가 그때 차례인 사람이어야 하고, 무효 행동이 하나라도 있으면 거부한다.
- 재생 결과의 `turnPlayer`, `result`, `publicBoard` 전체, `lastAction`이 저장값과 같아야 한다. 조작한 말 위치·`trail`·`pending`·`phase`·승패를 모두 거부한다.
- `log`가 비었으면 `lastAction`은 `null`이고 `stateVersion`이 0이거나, `{type:'REMATCH'}`이고 `stateVersion`이 1 이상이어야 한다.
