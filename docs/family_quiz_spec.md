# 🧩 오빠가 낸 문제 (가족 출제 퀴즈) 명세서

> **문서 버전**: v0.2 (2026-11-19)
> **상태**: 구현 완료(2026-11-19). 노션 DB `41ca27115b68801daa15dcd2844b913e`(사용자가 빈 표 생성, Claude가 열 13개 추가). 쓰기 차단 서버에서 출제실·풀이방·로비 카드 동작 확인, 실제 노션 쓰기 1건 시험은 사용자 승인 대기
> **근거**: 2026-11-19 사용자 요청 "민수 출제 퀴즈를 만들어 보자". 직업·경제 교육 글의 고학년 활동("AI와 함께 만드는 우리 집 해결사", "동생의 학습을 돕는 퀴즈 문제집", 버전 1.0 → 3.0)을 공부방에 옮긴다.
> **사용자 결정 (2026-11-19)**: ① 민수는 **공부방 출제 화면**에서 만든다 ② **바로 공개**, 부모님은 숨기기만 ③ 민서는 **로비 「오빠가 낸 문제」 카드**에서 푼다(새 문제가 있을 때만 보임) ④ 민수에게 가는 피드백은 **민서의 「이상해요」 신고**와 **가족 우체통 알림**. 보석 보상은 붙이지 않는다(보석 쓸 곳이 아직 재미없음).
> **승인 필요 이유**: 새 노션 DB를 만들고, 아이 화면에서 노션에 쓰기가 생긴다(상위 헌법 §7-7).

## 1. A (목표)
- 민수(5학년)가 동생 민서(1학년)를 위한 4지선다 문제를 **직접 기획·출제**한다. 민서가 푸는 모습이 곧 사용자 시험이고, 민서의 「이상해요」가 버그 신고다. 민수가 고치면 문제의 **버전이 1 → 2 → 3**으로 올라간다.
- 부모님은 평가자가 아니라 손님이다. 앱 안에 부모 검사 화면은 없다. 이상한 문제는 노션에서 `상태 = 숨김`으로 내린다.
- 학습 진도·보석·학습일지와 섞지 않는다. 정규 5분 퀘스트 흐름도 바꾸지 않는다.

## 4. D (데이터)

### 4-1. 노션 「가족 출제 DB」 (새로 만듦)
| 속성 | 유형 | 누가 씀 | 내용 |
| :--- | :--- | :--- | :--- |
| **문제** | `title` | 출제실 | 질문 글. 1~80자 |
| **정답** | `rich_text` | 출제실 | 1~20자 |
| **오답1·오답2·오답3** | `rich_text` | 출제실 | 각 1~20자. 정답·서로와 겹치면 안 됨 |
| **힌트** | `rich_text` | 출제실 | 0~60자. 틀렸을 때 읽어 줌. 비면 "정답은 ○○이야!"만 |
| **출제자** | `select` (민수, 민서, 엄마, 아빠) | 출제실 | 이번엔 늘 `민수` |
| **푸는사람** | `select` (민수, 민서) | 출제실 | 이번엔 늘 `민서` |
| **상태** | `select` (공개, 숨김) | 출제실·부모님 | 출시 = `공개`. 민수의 [내리기]와 부모님 노션 수정 = `숨김`. 지우지 않는다 |
| **버전** | `number` | 출제실 | 처음 1. 민수가 고칠 때마다 +1 |
| **고친날** | `date` | 출제실 | 출시·고칠 때 KST 날짜(`YYYY-MM-DD`, 로컬 날짜 헬퍼) |
| **푼버전** | `number` | 풀이방 | 민서가 마지막으로 푼 버전. 비어 있거나 `버전`보다 작으면 「새 문제」 |
| **결과** | `select` (한번에, 두번째에, 도움받음) | 풀이방 | 그 버전의 첫 풀이 결과 |
| **신고** | `select` (답이 이상해요, 무슨 말인지 모르겠어요, 글자가 틀렸어요) | 풀이방 | 민서의 「이상해요」. 민수가 고치면 비운다 |
| **메모** | `rich_text` | 부모님 | 앱은 읽지도 쓰지도 않는다 |

- 「새 문제」 = `상태=공개` 이고 `푸는사람=민서` 이고 (`푼버전` 없음 또는 `푼버전 < 버전`). 고친 문제는 다시 새 문제가 된다.
- 질의는 늘 `?force=true` (엣지 캐시 300초를 건너뛰어 방금 낸 문제가 바로 보이게). 쓰기는 `POST /v1/pages`·`PATCH /v1/pages/{id}` (기존 화면들과 같은 프록시 방식, `WORKER_PROXY_URL`).
- 판정은 위 열의 값으로만 한다. 문제·보기 글을 파싱하지 않는다(헌법 §8-5).

### 4-2. 화면 저장 값 (localStorage, 기기 편의용)
- `familyQuizDraft_minsu`: 쓰다 만 문제(새로고침해도 남게).
- `familyQuizMailAt_{minsu|minseo}`: 마지막 우체통 알림 시각(30분 묶음).
- 진도·결과는 저장하지 않는다(노션이 원본).

## 5. S (동작 규칙)

### 5-1. 출제실 (민수)
- **쓰기 칸**: 문제 / 정답 / 오답 3개 / 힌트(선택). 칸마다 글자 수를 보여 주고, 넘으면 저장 막음.
- **바로 경고 (막지는 않음)**: 문제가 40자 넘으면 "민서가 읽기엔 조금 길어요", 보기에 영어·어려운 한자어가 있어도 막지 않는다(민수의 판단).
- **막는 검사**: 빈 칸, 같은 보기 두 번, 정답과 같은 오답, 글자 수 초과. 「보기 순서는 민서 화면에서 자동으로 섞여요」 안내를 늘 보인다.
- **🔊 들어보기**: `speakFairyTTS`로 민서가 들을 문장 그대로 읽는다(질문 → 보기).
- **👀 민서처럼 풀어 보기**: 풀이방과 같은 함수로 이 한 문제를 띄운다. 노션에 기록하지 않는다.
- **🚀 출시**: 노션에 새 행(`버전 1`, `상태 공개`). 성공하면 목록 맨 위에 붙고 칸을 비운다. 실패하면 칸을 그대로 두고 "저장 못 했어요, 다시 눌러 주세요".
- **내 문제 목록** (최근 고친 순, 숨김 제외): 문제 글, `v2` 같은 버전 표시, 상태 칩 — `🆕 아직 안 풀었어요` / `✅ 한 번에 맞혔어요` / `🟡 두 번째에 맞혔어요` / `💡 도움받고 맞혔어요` / `🚩 이상해요: {이유}`(맨 위로).
- **[고치기]**: 칸에 불러와 고친 뒤 [🛠️ 고쳐서 다시 내기] → `버전+1`, `고친날` 갱신, `신고`·`결과`·`푼버전` 비움. 신고를 고치면 "버전 2 출시! 🐞 버그 하나 잡았어요" 연출.
- **[내리기]**: `상태 = 숨김`(확인 한 번). 목록에서 사라진다. 노션에는 남는다.
- **📮 알림**: 출시·고치기 성공 뒤, 이 기기가 우체통에 `민수`로 등록돼 있고 마지막 알림에서 30분이 지났으면 `FamilyMail.send({ to: 'minseo', text: '🧩 오빠가 새 문제를 냈어! 공부방에서 풀어 봐' })`. 등록 안 된 기기·실패는 조용히 넘어간다(출시는 성공으로 둔다).
- 출제실은 `user=minsu`일 때만 연다. 다른 값이면 로비로 돌려보낸다. (부모 출제는 범위 밖, §10)

### 5-2. 풀이방 (민서)
- 들어오면 새 문제를 `고친날` 오래된 순으로 **최대 3개** 가져온다. 0개면 "오빠 문제를 다 풀었어! 🎉" + [🏠 로비로].
- 문제마다 `QuizChoices.arrange`로 [정답, 오답1~3]을 섞는다(원래 번호 0 = 정답). 틀려서 다시 고를 때는 같은 순서.
- 0.3초 뒤 질문을 자동으로 읽는다(`speakFairyTTS`). 보기를 누르면 바로 채점 표시를 하고, 그 보기를 읽은 뒤 칭찬·격려 소리를 낸다(음성 끝 신호가 없으면 2.5초 뒤).
- **에러리스**: 맞으면 `fairyPraise()` + 반짝임. 틀리면 고른 보기만 흐려지고 `fairyEncourage()`, 하트·감점 없음. 두 번째도 틀리면 정답 보기가 노랗게 빛나고 힌트를 읽어 준 뒤 그 보기를 누르게 한다. 결과는 `한번에` / `두번째에` / `도움받음`.
- **🚩 이상해요**: 문제 카드 귀퉁이 작은 버튼 → 이유 3개 큰 버튼(그림+글자, 누르면 읽어 줌) → 고르면 "오빠한테 알려 줄게!" 하고 그 문제는 정답을 보여 준 뒤 넘어간다(결과는 `도움받음`).
- **기록**: 한 문제 끝날 때마다 `PATCH` (`푼버전 = 버전`, `결과`, 신고 있으면 `신고`). 실패하면 한 번 다시 시도, 그래도 실패면 다음에 다시 「새 문제」로 나온다(괜찮음).
- **끝**: 큰 스티커 "오빠 문제 다 풀었어!" + `fairyReward()`. 숫자·정답률은 보이지 않는다. 버튼 [🏠 로비로] (새 문제가 더 있으면 [🎁 하나 더!]).
- **📮 알림**: 이 기기가 `민서`로 등록돼 있으면 끝날 때 한 번 `FamilyMail.send({ to: 'minsu', text })`. 예: "🧩 민서가 오빠 문제 3개를 풀었어! 한 번에 맞힌 문제 2개, 🚩 이상해요 1개". 30분 묶음 규칙 같음.
- 보석·사탕·학습일지·5분 퀘스트 숙련도에는 손대지 않는다.

### 5-3. 로비 카드
- 민서 로비: 5분 퀘스트 버튼 바로 아래 빈 자리 `<div id="familyQuizCard" hidden>`. 로비가 그려진 뒤 `FamilyQuiz.mountLobbyCard(el, 'minseo')`가 새 문제 수를 한 번 읽어 1개 이상이면 "🎁 오빠가 낸 문제 N개!" 카드를 보인다. 실패·0개면 숨긴 채로 둔다. 로비 첫 그리기를 막지 않는다(비동기, 오류 삼킴).
- 민수 로비: 4칸 허브 아래 한 줄 버튼 "🧩 동생 문제 만들기" (늘 보임). `mountLobbyCard(el, 'minsu')`가 신고가 있으면 "🚩 1" 배지를 붙인다.

## 6. 안전
- 아이가 쓴 글은 화면에 `textContent`로만 넣는다(`innerHTML` 금지).
- 노션 쓰기는 이 DB 행만. 지우기(`archived`) 기능은 없다.
- 화면 검증은 쓰기 차단 서버(`guarded_preview_server.py`)로 한다. 실제 쓰기 시험은 사용자 승인 뒤 1건만, 끝나면 `상태=숨김`으로 내린다.

## 7. 단계
1. 이 명세 승인.
2. 노션 DB 만들기 (§4-1). 부모 페이지가 노션 연결에 열려 있지 않아(403) 사용자가 빈 표를 만들고, Claude가 프록시 `PATCH /v1/databases`로 열을 채웠다(2026-11-19).
3. `family-quiz-store.js` + 시험.
4. 풀이방 → 출제실 (풀이 함수를 출제실 미리보기가 재사용).
5. 로비 연결, 버전 꼬리표, 문서 동기화.
6. 시험 전체·계약 검사·쓰기 차단 서버에서 두 화면 확인 → 사용자 승인 뒤 실제 쓰기 1건.

## 8. T (시험) — `tests/family-quiz.test.mjs`
