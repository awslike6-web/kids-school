# 📊 실사용 리포트 (study_usage_report) 명세

> 목적: 아이들이 공부방을 **실제로 얼마나·무엇을** 쓰는지, **어디서 막히는지**를 노션에서 읽기만 해서 한 장으로 요약한다. 월말 점검(2026-12-21)과 겨울방학 구조 개선, 루틴 라인 「오늘의 길」의 「다시 보기」 정거장 설계의 근거 자료다.
> 위험도: **화면 없는 새 도구(읽기 전용)** → 자동 관문만(GEMINI.md §9). 노션 쓰기 0건.
> 작성: 2026-11-23 Claude Code. 근거: 노션 읽기 전용 표본(2026-11-21~23), `docs/learning_record_spec.md`.

## 0. 원칙

1. **읽기만 한다.** 노션은 `POST /v1/databases/{id}/query`와 `GET /v1/pages/{id}`만. Worker(`minmin-notion`) 경유, `User-Agent` 헤더 필수.
2. **앱과 같은 계산을 쓴다.** 공부 시간은 화면 시간 보상과 같은 `kids/core/study-activity.js`의 `measuredMinutes`, 숙련도는 `kids/subjects/quest/quest-mastery.js`의 `parseMastery`·`levelOf`·`isRusty`를 그대로 불러 쓴다(둘 다 `module.exports`가 있음). 문항기록 해석(`decode`)은 6줄짜리라 이 파일에 같은 규칙으로 두고, **시험이 앱의 `LearningLog.decode`와 같은 결과인지 대조**한다(실행 때 브라우저 모듈을 흉내 내 싣지 않는다).
3. **아이들 자료는 공개 저장소에 남기지 않는다.** 결과는 화면(표준 출력)에만, `--save`면 관제탑 `scratch/reports/`(git 추적 밖)에 저장. 저장소 안 경로에는 쓰지 않는다.
4. **자연어를 해석하지 않는다**(§8-5). 과목은 행의 `과목` 칸 글자 그대로(괄호 앞까지만 자른 이름으로 묶음, 예 `국어(미니독해_…)` → `국어`), 문항은 문항키로만 식별.

## 1. 실행

```bash
node scripts/study_usage_report.mjs [--days 30] [--since YYYY-MM-DD] [--until YYYY-MM-DD] [--child 민수|민서] [--fast] [--save] [--top 10]
```
- 기본 기간: 오늘(KST)까지 30일. `--since`/`--until`이 있으면 그것.
- `--fast`: 어휘 DB 전체 조회(약 16초)를 건너뛴다 → §2-4 정착률 생략, 막힌 문항은 이름 대신 키로 보여 준다(문항마다 따로 조회하면 오히려 느려진다).
- `--save`: `G:/master-tower/scratch/reports/study_usage_<since>_<until>.md`(관제탑 폴더가 없으면 OS 임시 폴더)에 같은 내용 저장.
- 종료 코드: 0 성공, 2 노션 조회 실패(부분 결과는 「조회 실패」 표시 후 계속 출력).

## 2. 섹션

### 2-0. 조회 범위와 행 나누기
- 학습일지는 `입장` 날짜로 걸러 조회한다: 기간 시작 **하루 전** ~ 끝 **하루 뒤**(노션 날짜 필터의 시각대·자정 넘김 대비). 그다음 코드에서 KST 날짜로 정확히 자른다(측정 시간은 `measuredMinutes`가 KST 날짜로 구간을 자르고, 일지 행은 `ID`의 날짜 부분이 아니라 `입장`의 KST 날짜).
- 행 나누기: `ID`가 `학습활동_`으로 시작하거나 `활동측정`이 비어 있지 않으면 **측정 행**, 그 밖은 **일지 행**. `학생=부모관리자` 행은 빼고 뺀 수만 한 줄.

### 2-1. 사용 시간·빈도 (측정 행)
- 아이별: 공부한 날 수(그날 **전체** 측정 시간 ≥1분인 KST 날짜), 총 공부 시간, 하루 평균, 요일 분포. 전체 시간은 그날 그 아이의 측정 행 **전부**를 `measuredMinutes(pages, child, date)`에 한 번에 넘겨 구한다(화면 시간 보상과 같은 값).
- 과목별: 과목마다 따로 `measuredMinutes`를 부른 값과 측정 행 수. 과목끼리 시간이 겹치거나 분 단위로 버려지는 몫이 있어 **과목별 합은 전체와 다를 수 있다**(표 아래에 「과목별은 참고값」 표시). **기간 중 0분인 과목**을 따로 표시(아이별 과목 목록: 민수 국어·수학·영어·사회·과학·하루·용어사전, 민서 국어·수학·영어·하루·용어사전 — 민서는 사회·과학을 보관함에 둠, GEMINI.md §2-2).

### 2-2. 문항 기록 요약 (학습일지의 `문항기록` 칸)
- 아이·과목별: 문항 수, 시도 수, **첫 시도 정답률**(=1 − 틀림/시도), 힌트 비율(힌트/시도), 출처 비율(접두어 `v`·`c`·`r`·`s`·`g`).
  - 「시도」는 그 문항을 **받은 횟수**이고 「틀림」은 그중 첫 선택에서 못 맞힌 횟수다. 한 번 받은 문항에서 틀리고 다시 골라 맞혀도 `[1,1]`(시도 1)로 남는다(`docs/learning_record_spec.md` §3). 그래서 1 − 틀림/시도가 곧 「받은 문항 중 첫 선택에 맞힌 비율」이다.
- 같은 문항키는 여러 날 행에 걸쳐 합산한다(시도·틀림·힌트 더하기, 최근 오답은 가장 늦은 날 것 3개).

### 2-3. 막힌 문항 Top N (아이·과목별)
- 후보: 틀림 ≥1(한 번이라도 첫 선택에서 틀린 문항, 두 번 다 맞힌 문항은 막힌 게 아님 — 2026-11-23 실제 실행 뒤 고침). 정렬: 틀림 수 내림차순 → 틀림 비율 → 시도 수.
- 표시: 이름(아래 §3), 시도/틀림/힌트, 최근 오답 글자.
- 수학 `g:` 유형은 따로 **유형별 첫 시도 정답률** 표(예 `vm-add-3x2-carry 4/7`).

### 2-4. 3·3·3 정착 (어휘 DB `숙련도`, `--fast`면 생략)
- 기간 안에 `lastReviewed`가 있는 어휘만. 아이·과목별 Lv(`levelOf`) 분포, 은메달(`count≥6`)·금메달(`count≥9`)·녹슨 왕관(`isRusty`, 오늘 기준) 수.
- `숙련도`는 행마다 한 칸이라 아이별로 나뉘지 않는다. `학생`이 한 아이뿐인 행은 그 아이 것으로, **`공통`이거나 두 아이가 모두 있는 행은 「공통(누구 것인지 구분 불가)」 묶음으로 따로** 센다(두 아이에게 중복으로 넣지 않는다).

### 2-5. 저장 칸 점유율 (인벤토리 DB, 학습일지)
- 인벤토리 아이별 `학습설정`·`월드기록`·`런너기록`의 **글자 수(조각들의 글을 이은 UTF-16 길이, JS `.length`)와 조각 수**, 한계 대비 %: `학습설정`은 앱이 한 조각으로 저장하므로 **한 조각 2,000** 대비(넘으면 저장 실패, 2026-11-21 측정 1,220·1,295자), `월드기록`은 앱 상한 1,800 대비, `런너기록`은 한 조각 2,000 대비. **60% 이상 ⚠️**.
- 학습일지 `문항기록` 가장 긴 행의 글자 수와 조각 수(참고, 조각당 1,900 단위로 나뉨).
- (가족 우체통·「오빠가 낸 문제」·마음일기 집계는 v1에서 뺀다 — 설계 검토: 목적 밖·조회 DB가 늘어 실패 지점만 늘어남. 필요하면 다음 판에.)

## 3. 문항키 → 이름

| 접두어 | 이름 찾기 |
| :--- | :--- |
| `v:` | 어휘 DB 행 `단어`(전체 조회를 이미 했으면 거기서, `--fast`면 `GET /v1/pages/{id}`) |
| `c:` | 교재 DB 행 `제목`(`GET /v1/pages/{id}`) |
| `r:` | 독해 지문 ID + 문항 번호 그대로(예 `minseo_1-2_u2_01 #1`). 노션 지문 page_id면 독해 DB 행 제목 |
| `s:` | 키 그대로(정적 자료, 예 `sci-report-1 #3`, `cc-5-2-L11 #18`) |
| `g:` | 유형 이름 그대로(§2-3 유형 표) |
- 조회 실패한 키는 키를 그대로 보여 준다(리포트 전체를 멈추지 않음). page_id 조회는 같은 키를 한 번만, 차례로(노션 초당 요청 한도).

## 4. 구조

- `scripts/study_usage_report.mjs` (ESM, 400~600줄). 순수 집계 함수는 `export`하고, 직접 실행할 때만 `main()`(노션 조회·출력)을 돈다(`import.meta.url === pathToFileURL(path.resolve(process.argv[1])).href` — 상대 경로로 실행해도 맞게).
- 내보낼 순수 함수(시험 대상): `kstDate(ms)`, `parseArgs(argv, today)`, `subjectGroup(raw)`, `splitLogRows(pages)` → `{ activity, daily }`, `usageSummary(activityPages, children, dates, measuredMinutes)`, `mergeItemRecords(dailyPages, decode)` → `{ [child]: { [subject]: { [key]: [시도,틀림,힌트,오답배열] } } }`, `itemSummary(merged)`, `stuckItems(merged, top)`, `mathTypeTable(merged)`, `masterySummary(vocaPages, child, since, today, qm)`, `fieldUsage(inventoryPages, dailyPages)`, `renderMarkdown(report)`.
- 앱 모듈 불러오기: `study-activity.js`·`quest-mastery.js`는 `createRequire`로(둘 다 `module.exports` 있음). `decodeItems(text)`는 이 파일에 두고 시험이 앱 `decode`와 대조.
- 노션 조회 도우미는 이 파일 안에 하나(`query(dbId, filter)` 페이지 넘김, `getPage(id)`, 둘 다 `?force=true` 없이 — 읽기 리포트라 엣지 캐시 5분 지연은 괜찮다).

## 5. 시험 (`tests/study-usage-report.test.mjs`, 노션 미접속)

1. `parseArgs`: 기본 30일, `--since/--until/--child/--fast/--save/--top`, 잘못된 날짜·아이 이름은 오류.
2. `splitLogRows`: `학습활동_` ID 또는 `활동측정` 있는 행 = 측정(빈 측정 행도), 그 밖 = 일지, 관리자 행 제외 수, KST 기간 밖 행 제외(하루 앞뒤 여유로 받아 온 행).
3. `usageSummary`: 실제 `measuredMinutes`로 전체(한 번에)·과목별(따로) 시간, 공부한 날은 전체 기준, 0분 과목 표시(민서는 사회·과학 제외).
4. `decodeItems`가 앱 `LearningLog.decode`(vm으로 실은 실제 파일)와 같은 결과(빈 칸·깨진 글·다른 버전·정상), `mergeItemRecords`·`itemSummary`: 여러 날 같은 키 합산, 첫 시도 정답률·힌트 비율, 깨진 행은 건너뛰고 수를 셈.
5. `stuckItems`: 정렬·후보 조건·Top N, `mathTypeTable`: `g:` 유형별 정답률.
6. `masterySummary`: 실제 `parseMastery`·`isRusty`로 은·금·녹슨 왕관, 기간 밖 `lastReviewed` 제외, `공통`·두 아이 행은 「공통」 묶음(아이별에 중복 없음).
7. `fieldUsage`: UTF-16 길이·조각 수, 60% 이상 ⚠️, 문항기록 최장 행.
8. `renderMarkdown`: 섹션 머리가 모두 있고 아이 이름 외 개인정보 칸(문항 본문·오답리포트 원문)을 넣지 않는다.
