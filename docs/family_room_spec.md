## 0. 진행 방식
- **단계마다 먼저 계획(파일별 내용·예상 줄 수, 이 문서와 다르게 하려는 점)만 보고하고 멈춘다.** 승인 메시지를 받으면 구현한다.
- 단계는 §9의 순서를 따른다. Worker는 관제탑 저장소, 화면은 공부방 저장소에 있으므로 작업 폴더와 브랜치를 저장소마다 따로 만든다.
- 운영 배포(`wrangler deploy`)와 `main` 병합·푸시는 구현 담당이 하지 않는다.
- **완료 보고 규칙**: 실행한 시험 명령과 출력 마지막 10줄 원문, 파일별 줄 수 표, 커밋 해시 또는 "커밋 못 함", 하지 못한 것.

## 1. A (목표)
거실에서 가족이 **각자 폰·태블릿으로 같은 판**에 들어와 야추·오목을 한다. 내 차례에 내 기기에서 누르면 모든 기기에 곧바로 보인다.

- 한 기기 모드는 지금 그대로 남는다. 인터넷이 없거나 기기가 하나면 예전처럼 한다.
- 한 기기를 둘이 함께 쓰는 경우(민서와 아빠가 태블릿 하나)도 된다.
- 말이 없는 TV·태블릿을 「구경」 화면으로 쓸 수 있다.
- 서버에 게임 규칙을 넣지 않는다. 윷놀이·장기·바둑을 추가할 때 Worker를 고치지 않아도 된다.

## 2. 연결 방식 결정

| 방식 | 판단 | 이유 |
| :--- | :--- | :--- |
| **Cloudflare Durable Objects + WebSocket** | ✅ 채택 | 방 하나당 단일 실행 지점이라 동시 입력의 순서가 하나로 정해진다. 이미 쓰는 Cloudflare 계정, 무료 요금제 사용 가능, 대기 중 절전(Hibernation) |
| 노션 폴링 | ❌ | 느리고, 이미 동시 호출에서 429를 겪었다. 게임 기록을 노션에 쓰지 않는 원칙에도 어긋난다 |
| Workers KV 폴링 | ❌ | 쓰기 반영이 최대 수십 초 늦을 수 있어 차례 게임에 맞지 않는다 |
| WebRTC 기기 간 직접 연결 | ❌ | 연결 중개 서버가 어차피 필요하고, 통신망·공유기에 따라 실패한다. 판의 원본을 어느 기기가 가질지도 복잡해진다 |
| Firebase 등 외부 실시간 DB | ❌ | 새 계정·SDK·아이 이름의 추가 저장처가 생긴다 |
| 같은 와이파이 안 로컬 서버 | ❌ | GitHub Pages(HTTPS) 화면에서 공유기 안 서버로 붙기 어렵다 |

**요금 판단**: 무료 요금제는 Durable Objects 요청 하루 100,000회(WebSocket 메시지 포함), 실행 시간 13,000 GB-s다. 5인 야추 한 판은 행동·심박을 합쳐 추정 1,000회 안쪽이고 대기 중에는 절전하므로 한도 걱정은 없다. 한도를 넘으면 오류가 날 뿐 과금되지 않으며, 그때는 §7의 「이 기기 하나로 이어서 하기」로 넘어간다. 무료 요금제는 SQLite 기반 클래스만 쓸 수 있다(`new_sqlite_classes`).

**Worker는 새로 만든다**: `workers/family-room/`, 이름 `family-room`. `minmin-notion`은 노션·TTS·보육비서 프록시와 비밀값을 함께 가진 공용 Worker이므로 놀이 기능 때문에 함께 배포·되돌리기 하지 않는다. 비밀값이 필요 없다.

## 3. 핵심 설계: 서버는 규칙을 모르는 심판
```
[기기 A]  엔진으로 다음 상태 계산 → act{baseRev:7, state} ─┐
                                                          ▼
                                     [방 Durable Object] rev가 7이면 저장, rev=8
                                                          │ 전체 스냅샷
[기기 A·B·C·TV] ◀────────────────────────────────────────┘ 받은 상태로 다시 그림
```
1. **규칙은 기기에 있다**: 기존 `YachtEngine`·`OmokEngine`을 그대로 쓴다. 서버는 상태를 내용 모르는 JSON으로 보관한다. Worker가 공부방 저장소의 엔진을 가져다 쓰면 두 저장소 사이에 사본이 생긴다.
2. **동시 입력은 `rev` 비교로 막는다**: `baseRev`가 현재 `rev`와 다르면 거절하고 최신 스냅샷을 보낸다. 엔진의 `stateVersion`은 쓰지 않는다. 야추 `start`의 `createGame`이 다시 하기에서 0으로 되돌리기 때문이다.
3. **서버 메시지는 사실상 스냅샷 한 종류**: 입장·재접속·행동·자리 변경 모두 같은 전체 스냅샷으로 받는다. 상태 크기가 작고(오목 15줄 최대 약 7KB) 재접속 처리를 따로 짤 필요가 없다.
4. **응답을 받은 뒤 그린다(낙관적 갱신 없음)**: 누르면 입력을 잠그고, 스냅샷이 오면 그린다. 되돌리기 코드가 필요 없다. 5초 안에 응답이 없으면 재접속한다.
5. **차례 검사는 기기 화면에서 한다**: 무르기(직전 착수자)·다시 하기처럼 차례가 아닌 사람의 행동이 있어 서버가 게임을 모르면 검사할 수 없다. 가족 놀이이므로 조작 방지는 목표가 아니고, 잘못 누르기 방지가 목표다. 서버는 자리가 있는 구성원의 요청인지만 본다.
6. **주사위는 굴린 기기에서 만든다**: 같은 이유로 조작 방지는 범위 밖이다. 패를 숨기는 게임은 §10-1의 방법으로 추가한다.
7. **스냅샷은 받는 기기별로 만든다**: 지금은 `you`만 다르지만, 스냅샷 생성을 함수 한 곳에 모아 나중에 기기별 비공개 값을 걸러 보낼 수 있게 둔다.

## 5. D (데이터·프로토콜)

### 5-1. HTTP
| 경로 | 설명 |
| :--- | :--- |
| `GET /health` | `{ ok, version }` |
| `POST /rooms` `{ gameType, maxSeats, client }` | 네 자리 코드 생성 후 `{ code }`. `client`가 첫 방장이 된다. 사용 중인 코드면 최대 5번 다시 뽑고 안 되면 503 |
| `GET /rooms/{code}/ws?client={uuid}` | WebSocket 연결 |

- **Origin 허용 목록**: `https://awslike6-web.github.io`, `http://localhost:*`, `http://127.0.0.1:*`. 그 밖과 Origin 없음은 403. 문자열 앞부분 비교가 아니라 URL로 파싱해 호스트를 정확히 비교한다(`localhost.evil.com` 거절). `POST /rooms`의 CORS 사전 요청도 같은 목록으로 응답한다. 임의 사이트에서 방에 붙는 것을 막는 용도이며 인증은 아니다.
- `gameType`은 `^[a-z]{2,16}$`, `maxSeats`는 2~5, `client`는 UUID 형식. 코드는 1000~9999.

### 5-2. 방 저장 값 (`room` 키 하나)
```json
{ "code": "4821", "gameType": "yacht", "maxSeats": 5, "phase": "lobby", "hostId": "uuid-a", "rev": 0,
  "lastActiveAt": 1793000000000, "state": null,
  "members": { "uuid-a": { "joinedAt": 1793000000000 } }, "kicked": [],
  "seats": [ { "id": "p1", "owner": "uuid-a", "name": "민서",
               "avatar": { "type": "emoji", "value": "🐰" }, "assist": "helper" } ] }
```
- `seats[].id`는 서버가 `p1`부터 붙이며 게임 상태의 `players[].id`와 같다. 대기실에서는 자리가 바뀔 때마다 다시 붙이고, 시작 뒤에는 바뀌지 않는다.
- `phase`는 `lobby` 또는 `playing`. 진행 중 게임 상태는 `state`에 그대로 둔다.
- **`rev`가 오르는 때**: 자리·게임 상태가 바뀔 때 모두(`seats`, `start`, `act`, `kick`, `lobby`, 대기실의 `leave`). 방장이 옛 자리 목록으로 시작하지 못하게 하기 위해서다. 진행 중의 `claim`·`leave`는 주인만 바뀌므로 올리지 않아 다른 사람의 행동이 거절되지 않는다. 연결 상태 변화도 올리지 않는다.

### 5-3. 기기 → 서버
| 메시지 | 누가 | 처리 |
| :--- | :--- | :--- |
| `seats { seats:[{name,avatar,assist}] }` | 구성원, 대기실 | 내 자리들을 통째로 교체. 전체 인원 `maxSeats` 이하, 말 중복 불가. 빈 배열이면 구경 |
| `start { baseRev, state }` | 방장 | 자리 2개 이상. `phase`를 `playing`으로, 방을 잠금 |
| `act { baseRev, state }` | 자리 있는 구성원 | `rev`가 같을 때만 저장·`rev+1` |
| `claim { seatId }` | 구성원 | 주인이 오프라인이거나 없는 자리, 또는 방장은 언제나 넘겨받기 |
| `kick { client }` | 방장, 대기실 | 내보내고 자리 삭제. 이 방에 다시 못 들어옴 |
| `lobby {}` | 방장 | `state` 비우고 대기실로, 잠금 해제 |
| `leave {}` | 본인 | 대기실이면 구성원·자리 삭제, 진행 중이면 자리의 `owner`를 `null`로 하고 구성원은 남긴다(돌아와 다시 넘겨받을 수 있음). 소켓은 코드 1000으로 닫는다 |

- 사람 입력은 이름뿐이다. 자유 채팅은 만들지 않는다.
- **자리 검사**: 이름 1~8자, `assist`는 `helper`·`tactic`·`classic`. 말은 이모지이거나 `spriteUrl`이 `https://raw.githubusercontent.com/awslike6-web/kids-archive/`로 시작하는 갤러리 그림만.
- `state`는 직렬화 64KB 이하, 메시지 전체는 128KB 이하. 넘으면 거절.

### 5-4. 서버 → 기기
- `snapshot { room:{code,gameType,maxSeats,phase,hostId,rev}, members:[{id,online}], seats, state, you }`
- `rejected { reason }`: 뒤이어 최신 `snapshot`을 보낸다. 기기는 조용히 다시 그린다(경고음 없음).
- **종료 코드**: 4404 없는 방, 4403 시작했거나 내보낸 방, 4409 같은 기기의 다른 창에서 다시 연결함(이 코드를 받은 창은 **자동 재접속하지 않는다**. 두 창이 서로 끊어 내는 반복을 막는다), 4400 형식 오류.

### 5-5. 서버 동작
- **절전 API 사용**: `ctx.acceptWebSocket(ws, [clientId])`, `setWebSocketAutoResponse`로 심박 응답(방을 깨우지 않음). 기기는 25초마다 심박.
- **입장**: 대기실이면 새 구성원 허용(방당 최대 8기기), 진행 중이면 기존 구성원만.
- **방장 승계**: 방장이 오프라인이면 온라인인 구성원 중 가장 먼저 들어온 기기로 `hostId`를 옮긴다. 방장이 돌아와도 되돌리지 않는다.
- **절전 복귀**: 방 값을 메모리 변수에 믿고 두지 않는다. 메시지·연결·알람마다 저장소에서 읽는다. 온라인 여부는 `ctx.getWebSockets(clientId)`로 구하고, 닫히는 중인 소켓은 빼고 센다.
- **보관 기간**: 마지막 활동 24시간 뒤 알람으로 `deleteAll()`. 연결된 소켓은 4404로 닫는다. 알람은 행동마다 다시 걸지 않고, 울렸을 때 `lastActiveAt`을 보고 아직이면 다시 건다.
- **로그**: 이름·말·게임 상태를 `console.log`에 남기지 않는다. 노션에 쓰지 않는다.

## 6. 화면

### 6-1. 시작 흐름
1. 게임 첫 화면 맨 위에 **[📱 이 기기 하나로]**(지금 화면, 기본) / **[📱📱 여러 기기로]**. 이어하기 화면이 먼저 뜨는 동작은 그대로다.
2. 여러 기기로 → **[방 만들기]** / **[코드 넣기]**(숫자 키패드 `inputmode="numeric"`, 네 칸). `?room=4821`로 열면 코드가 채워진다.
3. **대기실**: 방 코드를 크게 표시, [링크 보내기](`navigator.share`, 없으면 복사), 들어온 사람과 연결 상태, 내 자리 카드. 말·이름·도움 단계는 `FamilyPlayers.createSetup({ count:1, min:1, max:1, isTaken })`을 재사용한다. 방장이 게임 옵션(오목 판 크기)을 고르고 [게임 시작]을 누른다.
   - [+ 이 기기에서 한 명 더]: 한 기기에 자리 여러 개.
   - [구경만 하기]: 자리 없이 판만 본다. 큰 글자의 가로 배치는 기존 CSS를 쓴다.
4. 시작 전까지 말은 먼저 고른 사람 것이다. 동시에 고르면 서버가 뒤의 요청을 거절하고 카드가 최신 상태로 돌아온다.

### 6-2. 게임 화면 연결부
현재 두 게임은 `state = next; persist(); render…` 모양으로 상태를 바꾼다(야추 4곳, 오목 4곳). 이것을 한 함수로 모은다.
```js
function commit(next) {
  if (!room) { state = next; persist(); afterChange(); return; } // 한 기기: 지금과 같음
  room.submit(next);                                             // 여러 기기: 응답으로 그림
}
```
| 항목 | 여러 기기 규칙 |
| :--- | :--- |
| 입력 | 지금 차례 자리가 **내 기기 것**일 때만 주사위·점수·판을 누를 수 있다. 남의 차례에는 배너가 「민서 차례예요. 기다려요」 |
| 무르기 | 그 자리의 주인 기기에서만 버튼이 켜진다 |
| 도움 표시 | 그 사람 기기에서만 보인다. 민수가 민서의 도움 표시를 보지 않는다 |
| 오목 미리보기 | `selected`는 내 기기에만 있고 보내지 않는다. 스냅샷을 받으면 지운다 |
| 야추 0점 확인창 | 스냅샷으로 상태가 바뀌면 닫는다. 기존 `version` 검사를 유지한다 |
| 야추 굴림 애니메이션 | 클릭이 아니라 `lastAction.type === 'ROLL'`과 `rev` 변화로 시작해 모든 기기에서 보인다 |
| 음성 | 여러 대가 동시에 말하면 울리므로 **차례 안내는 차례가 된 자리의 기기만**, 승부 음성은 방장 기기만, `fairyReward()`는 내 자리가 있는 기기에서 |
| 포커스 | 내 차례가 될 때만 옮긴다. 남의 수로 다시 그릴 때 빼앗지 않는다 |
| 다시 하기 | 누구나 누를 수 있고 `baseRev` 비교로 한 번만 적용된다 |
| 처음으로 | 방장은 대기실로, 그 밖은 [방 나가기] |
| 저장 | `familyYachtGame`·`familyOmokGame`을 쓰지 않는다. `familyRoomSession` = `{code,gameType,clientId}`만 저장 |

- **기기 식별**: `familyRoomClientId`(`crypto.randomUUID`)를 `localStorage`에 둔다. 저장이 막히면 메모리 값으로 진행하고 새로고침 뒤에는 새 구성원이 된다.
- **재접속**: 끊기면 1·2·4·8·15초 간격, `visibilitychange`·`online` 때 즉시. 화면 위에 「연결 중…」을 띄우고 입력을 잠근다.

### 6-3. 연결 상태 표시
경고음·빨간 오류 없이 작은 띠로 표시한다(에러리스). 「민서 연결 끊김 · [내가 대신 하기]」는 그 자리의 주인이 오프라인이거나 없을 때 다른 기기에 보인다.

## 7. 실패 상황
| 상황 | 동작 |
| :--- | :--- |
| 두 기기가 동시에 누름 | 서버가 하나만 받고 다른 쪽은 최신 판으로 다시 그림 |
| 폰이 잠김·앱 전환 | 돌아오면 자동 재접속, 그동안의 판을 스냅샷으로 받음 |
| 배터리 방전으로 한 사람이 못 돌아옴 | 다른 기기에서 「내가 대신 하기」(§5-3 `claim`), 방장은 언제나 가능 |
| 방장이 나감 | 방장 승계. 게임은 계속됨 |
| 같은 기기에서 두 창 | 나중 창이 이어받고 앞 창은 안내만 표시, 재접속 안 함 |
| 코드 오타·만료 | 「이 방을 찾지 못했어요」, 코드 입력으로 돌아감 |
| 서버 장애·무료 한도 초과·30초 이상 끊김 | 「이 기기 하나로 이어서 하기」 제공. 마지막 스냅샷의 `state`를 한 기기 모드로 넘긴다(상태 모양이 같으므로 변환 없음) |
| 게임 추가·갱신으로 기기마다 화면 버전이 다름 | 스냅샷 `state.v`·`gameType`이 다르면 입력을 잠그고 「새로고침해 주세요」 표시 |

### 8-3. 화면 (Claude)

### 10-1. 패를 숨기는 게임을 추가할 때 (타일·카드 게임)
이번 구현에는 넣지 않지만 구조가 막지 않는다. 게임을 만들 때 아래 중 하나를 고른다.

| 방법 | 내용 | 서버 변경 | 한계 |
| :--- | :--- | :--- | :--- |
| 화면에서 가리기 | 전체 상태를 모두에게 보내고, 화면이 내 패만 그린다 | 없음 | 개발자 도구로 통신 내용을 열면 남의 패가 보인다 |
| 서버에서 걸러 보내기 | 상태를 공개 판·자리별 비공개 패·뽑을 더미로 나눈다. 서버는 기기마다 그 기기 자리의 패만 보내고, 뽑기는 서버가 처리한다. 행동은 전체 상태 대신 바뀐 공개 판과 내 패를 보낸다 | 범용 메시지 추가, 규칙은 여전히 모름 | 통신 내용으로도 볼 수 없다. 구현이 더 든다 |

- 구경 기기에는 패를 보여 주지 않는다. 「내가 대신 하기」로 자리를 넘겨받으면 그 자리의 패는 넘겨받은 기기에 보인다.
- 「이 기기 하나로 이어서 하기」는 패를 숨길 수 없으므로 이런 게임에서는 제공하지 않는다.
- 상품 게임의 이름·그림은 쓰지 않는다(`docs/family_yacht_spec.md` §1과 같은 원칙).

## 11. 안전·개인정보
- **서버로 나가는 것이 새로 생긴다**: 앞선 두 명세의 "게임 기록을 서버로 보내지 않는다"는 원칙이 여러 기기 모드에 한해 바뀐다. 이름(자유 입력 8자)·말·판 상태가 Cloudflare에 최대 24시간 보관된 뒤 삭제된다. 한 기기 모드는 계속 아무것도 보내지 않는다.
- **네 자리 코드의 한계**: 추측이 가능하다. 그래서 시작하면 방을 잠그고, 대기실에서는 방장이 내보낼 수 있으며, 다른 사이트 접속은 Origin으로 막는다. 코드를 맞힌 외부인이 대기실에 있는 동안에는 이름이 보일 수 있다. 빠른 입장이 더 중요한 가족용 도구로 판단해 받아들인 위험이며, 대기실 구성원 목록을 시작 전에 확인하게 한다.
- 받은 이름은 `textContent`로만 넣는다. 기존 `family-players.js`·`yacht-ui.js`가 이미 그렇게 한다.
- **기기 ID는 비밀이 아니다**: 스냅샷의 구성원 목록에 들어가므로, 같은 방 사람이 마음먹으면 다른 기기인 척 다시 연결할 수 있다. 조작 방지가 목표가 아니므로(§3-5) 받아들인다.
