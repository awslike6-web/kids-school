## 0. 진행 방식
- **단계마다 먼저 계획(파일별 내용·예상 줄 수, 이 문서와 다르게 하려는 점)만 보고하고 멈춘다.** 승인 메시지를 받으면 구현한다.
- 단계는 §9의 순서를 따른다. Worker는 관제탑 저장소, 화면은 공부방 저장소에 있으므로 작업 폴더와 브랜치를 저장소마다 따로 만든다.
- 운영 배포(`wrangler deploy`), 노션 DB 만들기, 비밀값 넣기, `main` 병합·푸시는 구현 담당이 하지 않는다.
- **완료 보고 규칙**: 실행한 시험 명령과 출력 마지막 10줄 원문, 파일별 줄 수 표, 커밋 해시 또는 "커밋 못 함", 하지 못한 것.

## 1. A (목표)
민수·민서·엄마·아빠 네 사람이 **각자 폰**에서 공부방 앱으로 서로에게 짧은 메시지를 보낸다.

- **폰 알림**: 앱이 꺼져 있어도 받는 사람 폰에 "📮 민서: 엄마 나 숙제 다 했어!" 알림이 뜬다. 누르면 그 메시지가 열린다.
- **앱 팝업**: 로비나 우체통 화면을 보고 있을 때 새 메시지가 오면 카드 팝업이 뜬다. 안 읽은 메시지가 있으면 앱을 열 때도 뜬다.
- **우체통 화면**: 「받은 메시지 / 보낸 메시지」 두 탭. 보낸 메시지에는 상대가 읽었는지(✓ 읽었어요) 보인다.
- **기록은 노션에 남는다**: 모든 메시지는 노션 「가족 메시지 DB」에 한 줄씩 쌓인다. 부모님은 필요할 때 노션에서 보고, 메모 칸에 적어 둘 수 있다. 앱 안에 부모 감시 화면은 따로 만들지 않는다.
- **아이가 직접 쓴다**: 미리 만든 원터치 문장은 두지 않는다. 폰 자판(음성 입력 포함)으로 직접 쓰는 것이 글쓰기 연습이 된다. 대신 **이모지 고르기 판**은 네 사람 모두에게 준다.
- 주로 폰에서 쓴다. 집 컴퓨터에서도 화면은 열리지만, 컴퓨터 알림 등록은 안내하지 않는다.

## 2. 방식 결정

### 2-1. 폰 알림
| 방식 | 판단 | 이유 |
| :--- | :--- | :--- |
| **웹 푸시 (서비스 워커 + VAPID)** | ✅ 채택 | 공부방은 이미 홈 화면 설치용 `manifest.json`이 있다. 새 앱이나 계정 없이 네 사람 폰 모두에 보낼 수 있다. 푸시 발송은 무료다 |
| 디스코드 (`notify-relay`) | ❌ | 부모님 폰 알림을 디스코드로 넘기는 중계기다. 아이들은 디스코드를 쓰지 않는다 |
| 카카오톡 알림톡·문자 | ❌ | 사업자 등록·건당 요금이 든다 |
| 별도 알림 앱(ntfy 등) | ❌ | 아이 폰마다 앱을 하나 더 깔아야 하고, 누르면 공부방이 아니라 그 앱이 열린다 |

**기기 조건**: 네 사람 모두 **안드로이드 폰**이다(2026-11-16 사용자 확인). 아이폰 안내는 만들지 않는다.
- 크롬에서 공부방을 열고 「홈 화면에 추가(앱 설치)」 후 그 아이콘으로 열어 알림을 허용한다.
- 설치하지 않아도 크롬에서 알림을 받을 수는 있지만, 그러면 알림이 「크롬」 이름으로 온다. 설치하면 「공부방」 이름과 아이콘으로 오므로 설치를 권한다.
- 폰 절전 설정이 크롬을 「절전 앱」으로 묶으면 알림이 늦을 수 있다. 첫 설정 화면에 확인 방법을 한 줄 안내한다.

### 2-2. 메시지 저장
| 방식 | 판단 | 이유 |
| :--- | :--- | :--- |
| **노션 DB에 저장 (단일 원천)** | ✅ 채택 | 사용자 요청. 부모님이 폰 노션 앱으로 언제든 보고 메모할 수 있다. 사본이 없어 어긋날 일이 없다 |
| Worker D1에 저장 + 노션에 사본 | ❌ | 저장처가 둘이면 읽음 표시·삭제가 어긋난다 |

메시지는 하루 수십 건 수준이라 노션 요청 한도(초당 평균 3회)에 걸리지 않는다. 안 읽은 메시지 확인은 화면이 보일 때만 하고 간격을 둔다(§6-3).

### 2-3. 서버
**새 Worker `family-mail`** (관제탑 `workers/family-mail/`). 하는 일은 셋이다.
1. 기기 등록과 신원 확인 (D1: 기기·알림 구독 정보만 저장, 메시지는 저장하지 않음)
2. 노션 읽기·쓰기 중계: `minmin-notion`을 **서비스 바인딩 `NOTION_PROXY`**로 부른다(보육비서와 같은 방식). 노션 토큰 사본을 만들지 않는다.
3. 웹 푸시 발송: VAPID 서명과 본문 암호화(RFC 8291·8292)를 WebCrypto로 직접 구현한다. 외부 npm 묶음을 쓰지 않는다.

`family-room`에 넣지 않는 이유: 그쪽은 비밀값이 없는 놀이용 Worker이고, 이쪽은 비밀값(VAPID 개인키·가족 코드)과 노션 쓰기를 가진다. 함께 배포하거나 되돌리지 않게 분리한다.

## 3. 핵심 설계

### 3-1. 누가 보냈는지는 서버가 정한다
```
[처음 한 번, 부모님이 각 폰에서]
  우체통 설정 → "이 폰은 누구 폰?" (민수/민서/엄마/아빠) + 가족 코드 입력
      → POST /register → 서버가 기기 토큰 발급 → 이 폰 localStorage에 보관

[그다음부터]
  메시지 보내기 → Authorization: Bearer <기기 토큰>
      → 서버가 토큰으로 보낸 사람을 찾는다 (화면이 보낸 사람을 정하지 않음)
```
- **가족 코드**는 Worker 비밀값이다. 공부방 화면 코드(공개 저장소)에는 없다. 부모님이 각 폰을 처음 설정할 때만 입력하고, 폰에는 저장하지 않는다. 아이들은 몰라도 된다.
- 아이 폰에서 「엄마」로 등록하려면 가족 코드가 있어야 하므로, 한번 등록한 뒤에는 남의 이름으로 보낼 수 없다.
- 공개 사이트라 화면 안에는 비밀을 숨길 수 없다. 기존 부모 비밀번호(`index.html`)는 소스에 보이므로 이 기능의 보안에 쓰지 않는다.

### 3-2. 보내기 순서
```
[보내는 폰] POST /send {to, text, clientId}
   → [family-mail] 토큰 확인 → 같은 clientId 메시지가 이미 있으면 그것을 돌려줌(재시도 중복 방지)
   → 노션 페이지 생성 (실패하면 오류, 화면은 쓴 글을 지우지 않고 남김)
   → 응답 200 {message}
   → (응답 뒤, waitUntil) 받는 사람의 등록 기기 전부에 푸시 발송
        404·410(구독 만료)이면 그 구독을 D1에서 지움
```
- 노션 저장이 성공해야 "보냈어요"다. 푸시가 실패해도 메시지는 남아 있고, 받는 사람이 앱을 열면 팝업으로 본다.

### 3-3. 읽음 표시
- 받은 사람이 팝업을 닫거나 우체통에서 그 메시지를 보면 `POST /read`. 서버는 그 메시지의 받는이가 요청한 기기의 주인일 때만 `읽음`·`읽은시각`을 고친다.
- 보낸 메시지 탭은 목록을 다시 읽을 때 읽음 상태를 보여 준다. 읽음을 실시간으로 밀어 주지는 않는다.

## 5. D (데이터·프로토콜)

### 5-1. 노션 「가족 메시지 DB」 (새로 만듦, 사용자가 직접)
| 속성 | 유형 | 누가 씀 | 내용 |
| :--- | :--- | :--- | :--- |
| **제목** | `title` | 서버 | `민서→엄마` 처럼 보낸이→받는이 (노션 목록에서 한눈에 보이게) |
| **보낸이** | `select` (민수, 민서, 엄마, 아빠) | 서버 | 기기 토큰으로 정한 보낸 사람 |
| **받는이** | `select` (민수, 민서, 엄마, 아빠) | 서버 | 받는 사람 한 명 |
| **보낸시각** | `date` (시각 포함, `+09:00`) | 서버 | KST. `toISOString().slice` 금지, KST 헬퍼로 만든다 |
| **내용** | `rich_text` | 서버 | 메시지 본문, 최대 500자 |
| **읽음** | `checkbox` | 서버 | 받는 사람이 읽으면 체크 |
| **읽은시각** | `date` (시각 포함) | 서버 | 읽은 KST 시각 |
| **메모** | `rich_text` | 부모님(노션에서 손으로) | 앱은 읽지도 쓰지도 않는다 |
| **메시지ID** | `rich_text` | 서버 | 화면이 만든 `clientId`(UUID). 재시도 중복 방지 |

- 노션 통합(Integration) 연결을 이 DB에 추가해야 프록시가 접근한다.
- DB ID는 `wrangler.toml`의 `MESSAGE_DB_ID`에만 둔다. 화면은 노션을 직접 부르지 않으므로 `kids/config.js`에는 넣지 않는다.
- 노션 질의는 항상 `?force=true`로 엣지 캐시를 건너뛴다(`minmin-notion` v4.6 확인 사항).
- 부모님이 노션에서 메시지 페이지를 지우면 앱 목록에서도 사라진다. 앱에는 삭제·수정 기능이 없다.

### 5-2. D1 표 `devices`
| 칸 | 내용 |
| :--- | :--- |
| `id` | 기기 번호 |
| `token_hash` | 기기 토큰의 SHA-256 (토큰 원문은 저장하지 않음) |
| `member` | `minsu`·`minseo`·`mom`·`dad` |
| `label` | "민수 폰" 같은 이름 (설정 화면에서 입력, 선택) |
| `endpoint`, `p256dh`, `auth` | 웹 푸시 구독 (알림을 허용하지 않은 기기는 비어 있음) |
| `created_at`, `last_seen_at`, `push_fail_count` | 관리용 |

한 사람이 기기를 여러 대 등록할 수 있다. 같은 기기에서 다시 등록하면 예전 줄을 지운다.

### 5-3. HTTP (모두 JSON, `Cache-Control: no-store`)
| 경로 | 인증 | 내용 |
| :--- | :--- | :--- |
| `GET /health` | 없음 | `{ ok, version }` |
| `GET /vapid-public-key` | 없음 | 알림 구독용 공개키 (화면에 하드코딩하지 않음) |
| `POST /register` | 가족 코드 | `{familyCode, member, label}` → `{deviceToken, member}` |
| `POST /subscribe` | 기기 토큰 | `{subscription}` 웹 푸시 구독 저장·교체 |
| `DELETE /device` | 기기 토큰 | 이 기기 등록 해제 |
| `POST /send` | 기기 토큰 | `{to, text, clientId}` → `{message}` |
| `GET /messages?box=inbox\|sent&cursor=` | 기기 토큰 | 20개씩, 최신순. `{messages, nextCursor}` |
| `GET /unread` | 기기 토큰 | `{count, more, items: [오래된 순 최대 3개]}` 팝업·배지용. 100개까지 세고 넘으면 `more: true`(화면은 "99+") |
| `POST /read` | 기기 토큰 | `{ids: [...]}` 내가 받은 메시지만 읽음 처리 |

- 메시지 객체: `{id, from, to, text, sentAt, read, readAt}`. `id`는 노션 `page_id` 원문이다.
- 검사: `to`는 네 사람 중 하나이고 보낸 사람과 달라야 한다. `text`는 앞뒤 공백 제거 후 1~500자다. 보내기는 기기당 1시간 30건까지다.
- CORS: `https://awslike6-web.github.io`, `http://localhost:*`, `http://127.0.0.1:*`만 허용한다. Origin은 위조할 수 있으므로 인증으로 치지 않는다(인증은 가족 코드·기기 토큰).

### 5-4. 푸시 본문 (암호화되어 전송)
```json
{ "type": "family-mail", "id": "<page_id>", "from": "minseo", "title": "📮 민서", "body": "엄마 나 숙제 다 했어!" }
```
- `body`는 내용 앞 60자. 잠금 화면에 내용 일부가 보인다.
- 안드로이드 상단 상태 표시줄에는 흑백 작은 아이콘(`badge`)이 필요하다. 없으면 크롬 기본 아이콘이 나온다. 2단계에서 흰색 우체통 모양 96×96 PNG를 만든다.
- TTL 1일, `Urgency: high`, 같은 보낸 사람 알림은 `tag`로 묶어 쌓이지 않게 한다.

### 5-5. 화면 저장 값 (localStorage)
`familyMailDevice = {token, member, label}` 하나만 둔다. 메시지 내용은 저장하지 않는다. 다만 쓰다 만 글은 `familyMailDraft`에 남겨, 보내기가 실패하거나 화면을 나가도 지워지지 않게 한다.

## 6. 화면

### 6-1. 첫 설정 (기기마다 한 번, 부모님이 해 줌)
1. 우체통을 처음 열면 「이 폰은 누구 폰인가요?」: 민수·민서·엄마·아빠 버튼. 아이 로비에서 들어오면 그 아이(`currentChild`)를 미리 골라 둔다.
2. 가족 코드 입력 → `/register`.
3. 「알림 받기」 버튼 → 알림 권한 요청 → 구독 → `/subscribe`. 권한 요청은 반드시 버튼을 누른 뒤에 한다(크롬은 누르지 않은 요청을 조용히 막는다).
   - 설치된 앱이 아니라 크롬 탭에서 열었으면 「크롬 메뉴 ⋮ → 홈 화면에 추가 → 그 아이콘으로 다시 열기」 안내를 먼저 보여 준다. 그래도 알림 버튼은 숨기지 않는다.
   - 알림을 거절하면 앱 안 팝업만 된다고 안내하고, 안드로이드 설정에서 다시 켜는 방법을 보여 준다.
4. 설정 칸(⚙️)에서 「이 기기 등록 해제」, 「알림 다시 연결」을 할 수 있다.

### 6-2. 우체통 화면 (`kids/common_space/family_mail.html`)
- 위: 「📥 받은 메시지 (안 읽음 N)」 / 「📤 보낸 메시지」 탭.
- 받은 메시지 한 줄: 보낸 사람 얼굴·이름, 내용, 시각(오늘이면 `오후 7:30`, 아니면 `11/14`). 안 읽은 줄은 강조. 누르면 펼쳐지고 읽음 처리, 「답장」 버튼.
- 보낸 메시지 한 줄: 받는 사람, 내용, 시각, `✓ 읽었어요 (오후 7:41)` 또는 `아직 안 읽었어요`.
- 아래: 「✏️ 메시지 쓰기」 → 받는 사람 고르기(나를 뺀 세 명) → 글 상자 → **이모지 판**(약 24개, 누르면 글 커서 위치에 들어감) → 보내기.
- 🔊 **읽어 주기**: 받은 메시지마다 버튼. `speakFairyTTS(text)`로 읽는다(`window.speechSynthesis` 직접 호출 금지). 민서가 글을 읽기 어려울 때 쓴다.
- 테마: 민수·민서 기기는 각자 로비 테마 색, 엄마·아빠는 기본 밝은 색.

### 6-3. 팝업과 📮 배지
- **어디서**: `lobby.html`, `index.html`에서만 뜬다. 우체통 화면은 팝업 대신 배지·받은 목록을 바로 갱신한다(v0.2). 문제 풀이·퀘스트·보드게임 화면에서는 띄우지 않는다(공부 흐름을 끊지 않음. 폰 알림은 그대로 온다).
- **언제 확인하나**: 화면을 열 때, 숨겨졌다가 다시 보일 때(`visibilitychange`), 화면이 보이는 동안 90초마다 `/unread`. 서비스 워커가 푸시를 받았을 때 보이는 창이 있으면 `postMessage`로 알려 바로 확인한다.
- **팝업 카드**: 보낸 사람 얼굴, 내용, [🔊 읽어 주기] [💌 답장] [확인했어요]. 안 읽은 게 여러 개면 가장 오래된 것 하나와 「외 N개 더 → 우체통」. **바깥을 눌러도 닫히지 않고 「확인했어요」나 「답장」을 눌러야 읽음 처리한다**(v0.2, 초1이 반사적으로 닫아 못 보는 일 방지). 읽음 처리가 실패해도 이번 탭에서는 같은 팝업을 다시 띄우지 않는다.
- **소리**: 팝업은 소리를 내지 않는다(v0.2). 폰 알림 소리로 충분하고, 캐릭터 효과음(칭찬·힌트 대사)은 메시지 도착과 뜻이 맞지 않는다.
- **📮 배지**: 민서·민수 로비 헤더(`lobby.html` 민서 68행·민수 401행 부근 헤더)에 📮 칩과 안 읽은 개수. 누르면 우체통. 안드로이드 홈 화면 아이콘에는 알림이 남아 있는 동안 점이 저절로 찍히므로 따로 처리하지 않는다.
- **알림 누르기**: 서비스 워커가 열린 공부방 창이 있으면 그 창을 우체통으로 옮기고, 없으면 새로 연다(`family_mail.html?open=<id>`).

## 7. 실패 상황
| 상황 | 동작 |
| :--- | :--- |
| 노션 저장 실패·인터넷 끊김 | "못 보냈어요, 다시 눌러 주세요". 쓴 글은 그대로 남는다. 같은 `clientId`로 다시 보내므로 두 번 저장되지 않는다 |
| 응답을 못 받았는데 실제로는 저장됨 | 다시 보내면 서버가 `메시지ID`로 찾아 기존 메시지를 돌려준다 |
| 푸시 실패 | 메시지는 저장됨. 받는 사람이 앱을 열면 팝업으로 본다 |
| 구독 만료(404·410) | 서버가 그 구독을 지운다. 그 기기에서 우체통을 열면 「알림 다시 연결」을 띄운다 |
| 기기 토큰이 무효(등록 해제됨) | 401 → 화면이 저장 값을 지우고 첫 설정으로 간다 |
| 가족 코드 틀림 | 403. 5번 연속 틀리면 그 IP를 10분 막는다 |
| 노션 429 | 서버가 한 번 1초 뒤 다시 시도하고, 그래도 실패면 503. 화면은 다시 시도 안내 |
| 서비스 워커 미지원(구형 브라우저) | 우체통·팝업은 되고 폰 알림 설정만 숨긴다 |

## 11. 안전·개인정보
- 메시지 원문은 노션에만 저장한다. Worker 로그(`console`)에 내용·이름을 남기지 않는다. D1에는 기기 정보만 있다.
