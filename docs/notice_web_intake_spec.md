## 0. 진행 방식 (꼭 지킨다)
- **먼저 계획만 보고하고 멈춘다.** 계획에는 ① §4-3 예약 실행을 어떤 방법으로 할지(조사 결과), ② 내 브라우저에서 두 사이트가 로그인돼 있는지, ③ 바꿀 파일 목록을 적는다. 승인 메시지를 받으면 진행한다.
- 문서·스킬 변경은 브랜치 `antigravity/notice-web-intake`에서 작업하고 그 브랜치까지만 푸시한다. **`main`에 병합·푸시하지 않는다.**
- 예약 작업 생성, 윈도 작업 스케줄러 등록 같은 **설정 변경은 승인 뒤에만** 한다.
- 운영 노션에는 **알림장 DB(`e3f9b3917c2b48bfa3d47db4bd0545fd`)에 공식 도구로만** 쓴다. 다른 DB에 쓰지 않는다. 노션 API를 직접 부르지 않는다.
- 커밋 끝에 `Agent: antigravity (모델명)`을 쓴다(관제탑 `scripts/agent_commit_rules.json` 표기 그대로).
- **완료 보고 규칙**: 실행한 명령과 출력 원문을 그대로 붙인다. 읽은 알림장은 §3-2에서 저장한 원문 파일 경로로 증명한다. 하지 않은 일은 "하지 않음"으로 적는다. 실제로 확인하지 않은 것을 확인했다고 적지 않는다.

## 1. 목적
선생님이 하이클래스·클래스팅에 올린 알림장을 부모가 손으로 옮기지 않아도, 평일 오후에 자동으로 읽어 노션 알림장 DB에 등록한다. 등록은 기존 공식 도구와 4대 헌법을 그대로 따른다. 새 서버·웹훅·폰 설정은 만들지 않는다.

**폰 알림 + 웹훅 방식을 쓰지 않는 이유**: 폰 알림은 "더보기"로 잘려서 본문 전체가 온다는 보장이 없고, 폰 자동화 앱·Worker 배포·비밀 토큰이 필요하다. 웹은 본문 전체가 보이고 학교 두 사이트 외 다른 알림·문자를 건드리지 않는다.

## 3. 매일 실행 절차 (이 절이 스킬 본문의 원본)
### 3-1. 읽기
1. 두 곳(§2 표)만 연다. 하이톡·클래스톡 대화, 가정통신문, 광고, 다른 사이트·탭은 읽지 않는다. **댓글·좋아요·확인했어요 버튼은 누르지 않는다.**
2. 오늘(한국 시간) 올라온 「알림장」 글만 고른다. 없으면 "오늘 새 알림장 없음"으로 끝낸다.
3. 로그인 화면이 나오면 **즉시 멈추고** "하이클래스(또는 클래스팅) 로그인이 풀렸습니다"라고 보고한다. 아이디·비밀번호는 절대 입력하지 않는다.

### 3-2. 원문 보존 (검수용, 필수)
- 읽은 글의 화면 텍스트를 손대지 않고 `G:\master-tower\scratch\notices\raw\{받은날}_{아이}.txt`에 저장한다(첫 줄에 글 주소와 올린 시각). `scratch/`는 Git 제외 폴더다.
- 노션에 들어가는 메모는 반드시 이 원문 파일에 있는 문장이어야 한다. 검수자는 이 파일과 노션을 대조한다.

### 3-3. 데이터 파일 작성 (`timetable_diary_spec.md` §4 그대로)
- `받은날` = 글이 올라온 날. `날짜` = 아이가 그 알림장을 들고 학교 가는 날 = 다음 평일. 알림장에 휴일·재량휴업이 적혀 있으면 그다음 등교일. 확실하지 않으면 다음 평일로 두고 보고에 "등교일 확인 필요"라고 적는다.
- 아이별로 `제목: "알림장"`, `적용 범위: "일일 전체"` 항목 1개. 메모는 원문의 번호 줄을 **글자 그대로** 줄 목록으로 넣는다. 번호가 없거나 붙어 있으면 줄만 나누고 `1. 2. 3.` 번호를 붙인다.
- 원문에 없는 내용(교시, 준비물 추측, 이모지, 고정 시간표 일정)을 더하지 않는다(규칙 ④). 하이클래스 끝의 「오늘의 안전 수칙」 문단은 매일 붙는 고정 문구라 넣지 않는다.
- 우리 아이와 관계없는 줄(예: "○○ 제외", 다른 반 대상)은 빼고, 보고에 뺀 줄과 이유를 적는다(규칙 ③). 애매하면 빼지 말고 넣은 뒤 보고에 표시한다.
- 원문에 과목이 **글자로 적힌** 과제만 `과목별` 항목(`제목: "{과목} 알림장"`)을 추가한다. 과목을 추측하지 않는다.
- 파일: `G:\master-tower\scratch\notices\{날짜}.json`. **이미 있으면 읽어서 기존 항목은 한 글자도 바꾸지 않고** 새 항목만 더한다. 그 파일에 같은 아이의 `"알림장"`이 이미 있으면(부모가 손으로 넣은 것) 그 아이는 이번 회차에 아무것도 더하지 않는다.

### 3-4. 등록과 확인
```bash
cd G:\master-tower
python -X utf8 scripts/register_notices.py scratch/notices/{날짜}.json --dry-run
python -X utf8 scripts/register_notices.py scratch/notices/{날짜}.json
python -X utf8 scripts/register_notices.py scratch/notices/{날짜}.json --dry-run
```
- 첫 미리보기에 오류가 있으면 등록하지 않고 오류 원문을 보고한다.
- 마지막 미리보기에서 모든 항목이 `⏭️ 이미 있음`이어야 등록 성공이다. 세 번의 출력 원문을 보고에 붙인다.
- `register_notices.py`를 고치지 않는다. 날짜별 사본이나 일회성 스크립트를 만들지 않는다. 커밋·푸시하지 않는다(데이터 파일은 Git 제외).

### 3-5. 보고 형식
1. (있으면 맨 위) 로그인 풀림·읽기 실패·등교일 확인 필요
2. 아이별: 글 제목, 올린 시각, 원문 파일 경로, 등교일, 등록/건너뜀 건수
3. 원문에서 뺀 줄과 이유
4. §3-4 명령 출력 원문

## 4. 이번 작업 (1회 준비)
1. **스킬 만들기**: `.agent/skills/school-notice-intake/SKILL.md`. 본문은 §3을 그대로 옮기고, 맨 위 설명(description)에 "하이클래스·클래스팅 알림장 자동 수신·노션 등록, '알림장 가져와 줘' 요청"을 적는다. 그다음 `python scripts/sync_agent_skills.py` → `python scripts/sync_agent_skills.py --check` 통과.
2. **문서 연결**: `AGENTS.md`의 「알림장 등록」 줄과 「현재 스킬」 목록에 이 스킬을 한 줄씩 추가하고, `timetable_diary_spec.md` §4 끝에 "웹 자동 수신: [`notice_web_intake_spec.md`](notice_web_intake_spec.md)" 한 줄을 더한다. 이 문서의 상태 줄을 갱신한다. 그 밖의 파일은 바꾸지 않는다.
3. **예약 실행 조사 → 승인 → 설정**: 평일 **15:30, 20:30** 두 번(선생님 글은 보통 오후 2시쯤, 늦은 글 대비). Antigravity가 스스로 정해진 시각에 대화를 시작할 수 있는 방법(앱 내 예약 기능, 또는 윈도 작업 스케줄러에서 Antigravity 명령줄 실행 등)을 **실제로 확인해서** 계획 보고에 적는다. 확인하지 못한 방법을 된다고 적지 않는다. 방법이 없으면 "부모가 '알림장 가져와 줘'라고 말하면 스킬 실행"으로 두고 그렇게 보고한다.
4. **브라우저 로그인 확인**: Antigravity 브라우저가 사용자 크롬과 다른 프로필이면 두 사이트가 로그인 안 돼 있을 수 있다. 그 경우 사용자에게 그 브라우저에서 직접 로그인해 달라고 요청한다(네이버·카카오 비밀번호를 대신 입력하지 않는다).
5. **시범 1건**: 다음 실제 새 알림장(예상: 2026-11-13 금 오후 → 등교일 2026-11-16 월)에 §3 절차를 돌리고 §3-5 형식으로 보고한다. 이 1건은 사람이 손으로 먼저 등록하지 않도록 사용자에게 미리 알린다.
