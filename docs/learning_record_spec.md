# 📒 문항 단위 학습 기록 체계 (LearningLog) 명세

> 목적: 아이가 **어떤 문항을 몇 번 풀고, 몇 번 틀리고, 무엇을 골랐는지**를 과목·화면과 상관없이 같은 형식으로 모은다. 겨울방학(2027-01~02) 구조 개선과 루틴 라인 「오늘의 길」의 「다시 보기」 정거장이 이 기록을 읽는다.
> 위험도: **L3**(노션 STUDY_LOG_DB에 칸 추가) + L2(공통 코어 `kids/core/`). 노션 칸 추가는 사용자 승인 뒤에만, 교차 검토 필수(GEMINI.md §9).
> 작성: 2026-11-21 Claude Code. 근거 데이터: 노션 읽기 전용 표본(아래 §1).

## 0. 원칙

1. **측정과 기록을 나눈다.** 공부 시간 측정(`study-activity.js`, `활동측정` v2·v3)은 화면 시간 보상·Guardian Worker가 같이 쓰는 계약이라 **바꾸지 않는다.** 문항 결과는 새 칸 `문항기록`에만 쓴다.
2. **아이 화면은 그대로.** 에러리스 원칙: 틀려도 새 표시·소리·점수 변화가 없다. 기록은 조용히 쌓인다.
3. **기존 일지 행에 얹는다.** 「아이·KST 날짜·과목」 하루 1행(`ID = {학생}_{YYYY-MM-DD}_{과목}`, `study-log-store.js`)의 새 칸에 문항별로 합친다. 문항마다 행을 만들지 않는다(이미 한 달 1,500행, 전체 조회 30초).
4. **자연어를 해석하지 않는다**(§8-5). 문항은 ID로만 식별하고, 기존 `오답리포트`(사람용 문장)는 그대로 둔다.
5. **칸이 없으면 기록을 잃지 않는다.** 노션에 칸이 아직 없거나 쓰기가 실패하면 기기에 보관했다가 다음에 보낸다. 다른 칸 쓰기를 망치지 않게 `문항기록`은 **그 칸 하나만** PATCH한다(INVENTORY `월드기록`과 같은 규칙).

## 3. `문항기록` JSON v1

```json
{"v":1,"i":{"<문항키>":[시도,틀림,힌트,"오답1|오답2"]},"b":["배치ID", "..."]}
```

| 키 | 뜻 |
| :--- | :--- |
| `v` | 형식 버전 1 |
| `i` | 문항키 → `[시도, 틀림, 힌트, 최근오답]`. **시도** = 그 문항을 받은 횟수, **틀림** = 첫 시도에 못 맞힌 횟수, **힌트** = 힌트를 본 횟수, **최근오답** = 고른 오답 글자 최근 3개(각 20자까지, `|`로 이음, 문자열 안 `|`는 `/`로 바꿈) |
| `b` | 이미 합친 배치 ID 최근 10개(같은 배치를 두 번 보내도 한 번만 더함. 같은 배치는 실패 직후 다시 보낼 때만 겹치므로 10개면 충분) |

- **문항키** (출처 접두어 + ID, 콜론으로 구분)
  - `v:<노션 page_id에서 하이픈 뺀 32자>` — VOCA_DB 어휘(5분 퀘스트, 1차 연결)
  - `c:<page_id 32자>` — CURRICULUM_DB 문항(사료·실험, 2차)
  - `r:<독해 지문 ID>:<문항 번호>` — 독해(2차)
  - `g:<생성 규칙>` — 생성형(수학 연산 등, 3차). 문제 하나하나(`12x5`)가 아니라 **유형**(예 `g:mul2x1-carry`)을 키로 한다. 키 규칙은 3차에서 정한다
  - 형식 검사는 하나만: `^[a-z]:[^\s]{1,62}$`(접두어 한 글자 + 콜론, 64자 이하). 맞지 않으면 버린다(경고만). 접두어별 세부 규칙은 그 단계를 연결할 때 정한다.
- 크기: 문항 하나 약 50자 → 하루 한 과목 40문항이면 약 2,000자. 한 행 문항 상한 300개(넘으면 **새 문항만 받지 않는다** + 경고, 기존 문항 누적은 계속).
- 조각 나누기는 **코드 포인트 단위**(`Array.from`)로 1,900자씩 — UTF-16 서로게이트(이모지)가 경계에서 반으로 잘리지 않게.
- 단원·과목 정보는 넣지 않는다. 행에 과목이 있고, 단원은 문항키로 VOCA·CURRICULUM에서 찾는다.

## 4. 공용 부품 `kids/core/learning-log.js` (`window.LearningLog`)

### 4-1. API
| 함수 | 설명 |
| :--- | :--- |
| `attempt({ child, subject, key, firstTry, hinted, picks })` | 문항 하나의 결과를 기기 대기열에 더한다. `child`='민수'\|'민서', `subject`=일지의 과목 한글명(예 '영어'), `key`=§3 문항키, `picks`=고른 오답 글자 배열. 잘못된 값은 버리고 `false` |
| `flush()` | 대기열을 노션으로 보낸다(같은 키는 `navigator.locks`로 한 번에 하나). 실패분은 남긴다. Promise |
| `pending()` | 대기열 요약 `{ keys, items }` (시험·점검용) |
| `merge(stored, delta, batchId)` | 순수 함수: 저장된 JSON과 배치 delta를 합친 새 객체(배치 중복이면 그대로) |
| `encode(obj)` / `decode(text)` | 순수 함수: JSON ↔ 조각 배열·문자열. `decode`는 빈 칸이면 빈 v1, **해석 실패·다른 버전이면 `null`**(호출한 쪽이 그 행 보내기를 멈춘다 — 기존 기록을 빈 값으로 덮지 않기) |

### 4-2. 대기열
- 기기 저장소 `MINMIN_LEARNING_LOG_V1`: `{ "<학생>_<KST날짜>_<과목>": { first: 첫 시도 시각(ISO+09:00), pending: { 문항키: [시도,틀림,힌트,오답배열] }, inflight: null | { batch: "8자 ID", items: {...}, fails: 0 } } }`
- `attempt`는 **`pending`에만** 더한다. 보내기 시작할 때 `inflight`가 비어 있으면 `pending`을 통째로 `inflight`로 옮기고 배치 ID를 붙인다(이미 있으면 그 배치를 그대로 다시 보낸다). 성공하면 `inflight`만 지운다 → 보내는 동안 들어온 시도는 `pending`에 남아 다음 배치가 된다. 대기열 읽기·쓰기는 매번 저장소에서 새로 읽어 합친다(다른 탭과 공유).
- 보내는 때: 5분 퀘스트 레슨 완료, 페이지 로드 직후, 시도 20개마다. **페이지 숨김·닫힘 때는 보내지 않는다**(GET→POST→PATCH 연쇄가 중간에 끊긴다). `attempt`가 매번 기기에 저장하므로 잃지 않고 다음 로드 때 보낸다. 이 PATCH에는 `keepalive`를 쓰지 않는다(64KB 한도).
- 여러 키(여러 날·과목)는 **하나씩 차례로** 보낸다(노션 초당 요청 한도).
- 같은 배치가 연속 5번 실패하면(`fails`) 그 페이지 열람 동안은 더 보내지 않는다(다음 로드 때 다시). 404(기억한 페이지가 지워짐)는 기억을 지우고 `ID`로 다시 찾는다.
- 관리자 모드(`부모관리자`)·학생 이름이 없으면 기록하지 않는다.

### 4-3. 보내기 순서 (키 하나)
0. **칸 확인 먼저**: 그 페이지 열람에서 처음 보낼 때 `GET /v1/databases/{STUDY_LOG_DB}`로 `문항기록` 칸이 있는지 한 번 본다. 없으면 **아무 행도 만들지 않고** 대기열에 둔다(칸 추가 전 배포 시 빈 행이 쌓이지 않게). 결과는 그 열람 동안 기억한다.
1. 일지 행 찾기·만들기는 `StudyLogStore`와 **같은 잠금**(`minmin-study-log:{키}`) 안에서 한다 → 기존 학습일지 쓰기와 동시에 돌아도 같은 `ID` 행이 두 개 생기지 않는다. 행이 없으면 일지 행을 만든다: `입장`·`퇴장` = 대기열의 `first`(그날 첫 시도 시각, 지난 날짜면 그날 시각 그대로), `소요시간 0`, `오답리포트 '오답 없음'`, `문항기록`은 넣지 않음. 기존 학습일지 쓰기는 `입장`을 고치지 않으므로 첫 시도 시각이 그대로 시작 시각이 된다.
2. 행을 최신으로 다시 읽어(`readRememberedPage`는 이미 최신 GET) `decode`. `null`이면 이 키 보내기를 멈추고 경고(대기열 유지).
3. `merge(stored, inflight.items, inflight.batch)` → `encode` → `문항기록` **한 칸만** PATCH.
4. 성공하면 `inflight`를 지운다. 실패는 남긴다(같은 배치 ID로 다시 → 중복 합산 없음).
- 두 기기가 같은 순간 같은 키를 쓰면 한쪽 delta가 덮일 수 있다(드묾, 알려진 한계). 같은 기기의 탭끼리는 잠금으로 막는다.

### 4-4. `StudyLogStore`에 더할 것
- 일지 행 찾기·만들기를 다시 짜지 않도록 내보내기: `serialize(key, fn)`(같은 잠금 이름), `locateDailyPage(key)` → `{ page, failed }`(기억한 페이지 최신 GET → 없으면 `ID` 조회), `createDailyPage(entry, key)` → page. 기존 `writeStudyLog`도 이것들을 쓰게 정리(동작 같음). 연속 학습(스트릭) 표시는 문항기록 쓰기로 바뀌지 않는다.

### 4-5. 로드
- `study-log-store.js` 다음에 싣는다. `notion-helper.js`·`core.js` 등 학습일지를 싣는 곳(퀘스트 러너 포함)에 같은 버전으로 추가. `loadCoreScripts`가 파일 이름으로 중복을 거른다.

## 6. 시험 (`tests/learning-log.test.mjs`, 노션 미접속)

1. `merge`: 시도·틀림·힌트 합산, 최근오답 3개 유지·20자 자르기·`|` 치환, 같은 배치 두 번 = 한 번, 배치 목록 10개 유지, 문항 300개 상한(기존 문항 누적은 계속).
2. `encode`/`decode`: 1,900 코드 포인트 조각 왕복(이모지가 경계에 걸려도 깨지지 않음), 빈 칸 → 빈 v1, 깨진 글·다른 버전 → `null`.
3. `attempt`: 잘못된 키·학생·과목 버림, 관리자 기록 안 함, 같은 키 누적, `first` 시각 유지.
4. `flush` (모의 fetch): 칸 없음 → **행도 만들지 않고** 대기열 유지, 칸 있음 → `문항기록` 한 칸만 PATCH(다른 속성 없음, `keepalive` 없음), 실패 → 같은 배치 재전송 시 중복 없음, 보내는 중 들어온 `attempt`는 성공 뒤에도 `pending`에 남음, 행 없음 → `first` 시각으로 일지 행 생성 후 PATCH, `decode` null → PATCH 안 함, 5번 연속 실패 → 그 열람에서 멈춤.
5. 퀘스트 레슨 연결: `onDone` 결과가 `attempt`로 넘어가는지(가짜 DOM), 여러 ID 문항에는 오답 글자를 붙이지 않는지, 힌트를 보면 `hinted`가 넘어오는지.
6. `notion-contract.test.mjs`: `문항기록` 전송 속성이 도감과 같은지.
- 기존 시험(퀘스트 마스터리 성질 시험, 학습일지 성질 시험, 분리 규칙)이 그대로 통과.
