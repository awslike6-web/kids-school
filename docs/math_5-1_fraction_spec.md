## 2. 교과 근거와 한계

- **교과서 사진 없이 만든다** (사용자 결정 2026-11-24, 수학 공통). 5학년 1학기 성취기준과 단원 흐름을 따르고 쪽수를 적지 않는다. 교과서판마다 차례 이름이 조금 달라도 내용은 같다.
- 5-1 범위를 지킨다.
  - ① 약분과 통분: 크기가 같은 분수, 약분, 기약분수, 통분(공통분모), 분모가 다른 두 분수의 크기 비교, 분수와 소수의 크기 비교.
  - ② 분수의 덧셈과 뺄셈: 분모가 다른 진분수·대분수의 덧셈과 뺄셈(받아올림·받아내림 포함).
  - **답은 기약분수**로, 가분수는 대분수로 쓴다(4-2와 달리 이제 약분한다). 답을 고르는 질문에는 "기약분수로" 또는 "간단히(기약분수로) 나타내면"을 꼭 넣는다(약분 전 답이 크기는 같아도 오답인 까닭이 질문에 보이게).
- **풀이 방법은 하나씩만** (4-2 §2 원칙 그대로, 작업 기억 부담·방법 간섭 방지):
  - **약분·기약분수**: 분자와 분모를 **같은 작은 수(2·3·5·7)로 더 나눌 수 없을 때까지 나눈다**. "최대공약수로 한 번에 나누기"는 `💡 왜 그럴까?` 안에 "이렇게 하면 한 번에 끝나요" 한 줄로만 보여 주고 문제로 내지 않는다.
  - **통분**: **큰 분모의 배수를 차례로 세어, 작은 분모로도 나누어떨어지는 첫 수를 공통분모로 쓴다**(= 최소공배수). "분모끼리 곱하기"는 따로 가르치지 않는다. 서로소(2와 3)이면 이 방법이 저절로 곱(6)이 된다.
  - **크기 비교**: **통분해서 분자를 비교**하는 방법 하나. 분자가 같은 두 분수도 통분해서 비교한다("분자가 같으면 분모가 작은 쪽이 크다"는 따로 가르치지 않음 — 부등호 방향 간섭 방지). 막대 맞대기는 눈으로 확인하는 그림일 뿐 규칙으로 쓰지 않는다.
  - **대분수 덧셈·뺄셈**: 4-2와 같이 자연수끼리·분수끼리, 받아내림은 "자연수 1을 분모만큼 쪼개기"만. "가분수로 바꿔 계산하기"는 화면·퀴즈 어디에도 내지 않는다.
  - **분수 → 소수**: 분모를 10 또는 100으로 만들어 소수로 쓴다(2/5 = 4/10 = 0.4, 1/25 = 4/100 = 0.04). "분자 ÷ 분모 나눗셈"은 6학년이라 내지 않는다.

## 3. 공통 설계 (두 탐험관 모두)

4-2 명세 §3-0(많이 풀며 익숙해지기)·§3-1(화면 공통)을 **그대로** 따른다. 요점과 이번에 달라진 점만 적는다.

- 관은 바로 문제로 시작, 개념은 접힌 `[💡 왜 그럴까?]` 안, 1-2-3 계산 순서 카드는 늘 보임(`MathDrill.algo`·`why`·`expr`).
- 관 완주 = 3문제 한 판, 그 뒤 `[🔁 한 판 더]` 끝없이(`MathDrill.rounds`). 7관 ⚡ 연습 마당 = 1~6관 종류 섞은 10문제(`LAB_KINDS` 차례 = 쉬운 것 먼저), 끝없이 새 판. 탐험관 = 관 7개 + 퀴즈 배틀(감싸개 `mxTotal` 7).
- 더 풀기 보상: 맞힌 문제 10개마다 💎1, 화면마다 하루 3개(`MathDrill.counter`, 4-2와 같은 키 규칙).
- 에러리스 3지선다 `MathDrill.ask`(→ `ui.choiceQuestion`, `QuizChoices` 섞기, 오개념별 노란 힌트, 빨간 X·감점·경고음 없음). `＞ ＜ =` 비교 보기는 뜻이 있는 순서라 섞지 않는다(4-2 소수 3관과 같이 고정 — `QuizChoices`가 기호 보기를 알아서 고정하는지 구현 때 확인하고, 아니면 4-2 소수 3관과 같은 방법을 쓴다).
- **한 문제 = 고르기 한 번, 핵심 단계 3개 이내.** 조작(쪼개기·배수 세기)은 고르기 **전에** 하되, 조작이 답을 미리 보여 주면 안 된다. 답을 보여 주는 장면(약분 과정, 합친 막대)은 **정답을 고른 뒤 확인 장면**으로만 자동 재생한다.
- **나누기 버튼 줄은 디딤돌**: 약분 단계는 처음부터 펼치지 않는다. 아이가 "덜 약분한 답"·"약분 안 한 답" 보기를 고르면 노란 힌트 밑에 나누기 버튼 줄이 열려, 직접 나눠 본 뒤 남은 보기에서 다시 고른다(3관 ①②만 처음부터 펼친 조작 — 아래 표).
- 조작 버튼은 **높이 ≥ 56px**(1학년 다리와 같은 손가락 기준). 칸을 직접 누르지 않는다. 같은 버튼을 많이 누르게 하지 않는다(②에는 1칸씩 칠하기 버튼이 없다).
- **표기**: 화면의 모든 분수는 정식 세로 분수(틀 옵션 `fractions: true`). 코드·노션 글자 표기는 `3/5`, `2와 3/5`(받침이면 `1과 3/4`). 보기는 답만, 식은 질문에.
- 학습일지: 관 안 3지선다 모두 `MathDrill.ask`의 `prefix`·`kind`로 `g:frac5r-<kind>`(①)·`g:frac5u-<kind>`(②). 조작 단계, 디딤돌 나누기, 🪜 계단 질문은 기록하지 않는다. 퀴즈 배틀은 틀의 `c:<page_id>`.
- 보상: 틀 그대로(관 첫 완주 💎1, 7개 관 하루 1회 +5 `math_fracred_allclear_…`·`math_fracunl_allclear_…`, 퀴즈 문항 첫 정답 💎1).
- 음성: `speakFairyTTS`·`fairyPraise`·`fairyEncourage`·`fairyReward`만. 질문 자동 읽기는 틀 규칙 그대로.
- 🪜 계단 카드(`MathLadder.attach`, `onWrong` 첫 호출 때 붙음): 표의 🪜 관.
- 계단 이동 링크(감싸개 머리, 375px에서 한 줄에 들어가게 짧은 이름): ① `⬇ 4-2 분수` · `⬇ 약수와 배수` · `⬆ 분수 덧셈뺄셈`, ② `⬇ 약분과 통분` · `⬆ 분수의 곱셈`.
- **오답 보기 겹침 기준은 화면 글자 표기(`token`) 일치**다(크기 같음이 아님). 그래서 정답 `1/2`에 대한 "덜 약분한 답" `3/6`은 다른 보기로 남는다.

### 3-1. 이번에 새로 쓰는 그리기 조작 (두 화면 공용 `Frac5Draw`)

- **나눠지는 막대 `splitBar(d, n, cls)`**: 4-2 막대와 같은 모양(한 줄 하나, 폭 = 카드 안 폭, 높이 ≥ 44px). `resplit(k)`는 칸 하나하나가 k조각으로 갈라지는 짧은 장면(0.4초) 뒤 칸 수 d×k, 칠한 칸 n×k. `merge(k)`는 그 반대(칸이 k개씩 합쳐짐). 칠한 길이는 그대로 보인다. 칸 수는 **24 이하**, 칸 사이 1px 균등 분할(375px에서 칸 안 폭 약 11px 허용).
- **두 막대 맞대기 `pairBars(a, b)`**: 위아래로 같은 길이, 왼쪽 끝 맞춤. `resplitTo(d)`로 둘 다 공통분모 칸으로 갈라진다.
- **자연수 배지**: ②의 대분수는 자연수 부분을 막대로 그리지 않고 `자연수 3` 숫자 배지로, 분수 부분만 막대로 그린다(375px에서 통막대 여러 개가 넘치지 않게). 화면에 막대는 최대 3줄.
- **나누기 버튼 줄 `divideRow(f, onDone)`**: `[÷2] [÷3] [÷5] [÷7]` 큰 버튼 4개(한 줄 4칸, 칸 폭 ≥ 70px).
  - 분자·분모가 둘 다 나누어떨어지면: 분수가 바뀌고(`12/18 → 6/9`) 막대가 `merge`, `fairyPraise`.
  - 하나라도 안 나누어떨어지면: 그 버튼만 꺼지고 줄 아래 한 줄 안내("9는 2로 나누어떨어지지 않아요"), `fairyEncourage`. 분수가 바뀌면 꺼진 버튼은 다시 켜진다.
  - 어느 버튼으로도 더 나눌 수 없으면 줄이 잠기고 "더 나눌 수 없어요 = 기약분수" 반짝임, `onDone(기약분수)`.
- **배수 칩 줄 `multipleChips(big, small, onDone)`**: 큰 분모의 배수 칩(`8`, `16`, `24` …)이 한 번에 하나씩 켜진다. 켜진 칩 하나만 누를 수 있고, 판정 글은 **칩 줄 아래 한 줄 안내 영역**에만 쓴다("16 ÷ 6 → 나누어떨어지지 않아요" / "24 ÷ 6 = 4 ✓"). 처음 ✓인 칩이 공통분모가 되고 줄이 잠긴다. 칩은 최대 4개(공통분모 ≤ 24, 큰 분모 ≥ 6이면 4개 이하). 틀릴 길이 없는 세기 조작이다.
- **소수 띠 `decimalStrip(f, k, base)`**: `2/5` → `[×2 하기]` 버튼 한 번 → `4/10` → `[소수로 쓰기]` → `0.4`. 분모 100이면 소수 두 자리 칸 두 개(`0.04`는 첫째 칸에 0이 들어가는 장면). 0~1 눈금 막대(10등분)에 점을 찍어 위치를 함께 보여 준다.

## 4. ① 약분과 통분 탐험관 (`fraction_reduce.html`, key `fracred`)

**수 규칙**: 처음 분수의 분모 2~12(약분·기약분수 문제의 처음 분수는 분모 ≤ 24, 분자·분모 소인수는 2·3·5·7만). 통분 공통분모 ≤ 24. 6관만 분모 2·4·5·20·25·50(아래). 관마다 3문제(순서 고정, 수만 무작위).

| 관 | 배우는 것 | 활동 (문제 순서) | 🪜 |
| :--- | :--- | :--- | :---: |
| 1관 크기가 같은 분수 | 분자·분모에 같은 수를 곱하면 크기가 같다 | 카드: ①분모에 곱한 수를 ②분자에도 곱해요. ①`equiv-split` 칠한 막대(예 2/3) → `[칸을 2조각씩]`·`[3조각씩]`·`[4조각씩]` 중 문제가 정한 버튼 하나만 켜짐 → 쪼갠 막대를 보고 "칠한 부분을 분수로?"(보기 전체 분수) ②③`equiv-up` "2/3와 크기가 같은 분수 중 분모가 12인 것은?"(막대 그림 없이 식, 보기 전체 분수) | |
| 2관 약분하기 | 공약수로 나누기 | 3지선다만(조작 없음), 정답 뒤 확인 장면으로 막대 `merge`. ①`reduce-by-2` "12/18을 2로 약분하면?" ②`reduce-by-3` ③`reduce-which` "12/18을 약분할 수 있는 수는?"(보기 자연수: 공약수 1개 + 분자만 또는 분모만 나누어지는 수 2개) | ✓ 공약수 |
| 3관 기약분수 | 더 나눌 수 없을 때까지 | ①②는 **조작이 문제**: 나누기 버튼 줄로 줄이 잠길 때까지 나누면 맞힌 것으로 센다(고르기 없음, `ask` 대신 조작 완료가 정답 1개). ①`simplest-1` 한 번이면 끝(6/9) ②`simplest-2` 두 번 이상(12/18 → 6/9 → 2/3). ③`simplest-pick` "기약분수인 것은?" 3지선다(보기 3개 중 기약분수 1개, 오답 2개는 약분되는 분수) | |
| 4관 통분하기 | 공통분모 찾기 | 배수 칩 줄로 공통분모 찾기 → `pairBars.resplitTo` → "통분한 두 분수는?" 3지선다(보기는 문제 순서대로 두 분수 한 쌍, 예 5/6·3/8 → `20/24, 9/24`. 375px에서 세로 1열 전폭 버튼). ①`common-multiple` 한 분모가 다른 분모의 배수(1/2, 3/8 → 8) ②`common-coprime` 서로소(2/3, 1/4 → 12) ③`common-lcm` 그 밖(5/6, 3/8 → 24) | ✓ 배수 |
| 5관 분수의 크기 비교 | 통분해서 비교 | 맞댄 두 막대(통분 전) → `[통분하기]` 버튼(`resplitTo`, 아래에 통분한 두 분수 한 줄) → "□ ○ □ 알맞은 기호는?" `＞ ＜ =`. ①`compare-same-num` 분자가 같은 두 분수(2/3 vs 2/5 → 15, 3/4 vs 3/8 → 8 처럼 공통분모 ≤ 24) ②③`compare-unlike` | |
| 6관 분수와 소수 | 분모를 10·100으로 | 소수 띠. 카드: ①분모가 10이나 100이 되게 곱해요 ②10이면 소수 한 자리, 100이면 소수 두 자리로 써요. ①`to-decimal-10` (분모 2·5, 대분수 자연수 1~3 포함: 1과 2/5 = 1.4) ②`to-decimal-100` (분모 4·20·25·50, 소수 둘째 자리 끝 0 없음, 1/25 = 0.04처럼 첫째 자리 0 포함) ③`compare-decimal` "0.7 ○ 3/5 알맞은 기호는?" (분수를 소수로 바꿔 비교) | |

- 🪜 계단 카드: 2관 「공약수」(12와 18을 둘 다 나누어떨어지게 하는 수, 쉬운 3지선다 1개), 4관 「배수」(4의 배수 4·8·12…, 쉬운 3지선다 1개). `division_factors.html`로 나가지 않고 관 안에서 접혔다 펼쳐진다.
- **오개념 힌트** (고른 보기마다, `mistake` 이름은 코드에서 씀):
  - `add-same` 크기가 같은 분수에서 분자·분모에 같은 수 더함(2/3 → 3/4): "같은 수를 **곱해야** 크기가 같아요. 막대를 쪼개 봐요."
  - `add-diff` 분모 차이만큼 분자에 더함(2/3 = □/12 → 11/12): "분모에 4를 곱했으니 분자에도 4를 곱해요."
  - `denom-only` 분모에만 곱함(2/3 → 2/12): "분모에 곱한 수를 분자에도 곱해요."
  - `subtract` 약분 때 빼기(12/18 → 10/16): "약분은 빼기가 아니라 같은 수로 **나누기**예요."
  - `num-only`·`den-only` 분자만·분모만 나눔(12/18 ÷2 → 6/18): "분자와 분모를 둘 다 나눠요."
  - `not-common` 분자 또는 분모 하나만 나누어지는 수를 고름(12/18에서 4): "18은 4로 나누어떨어지지 않아요. 둘 다 나누어지는 수를 찾아요."
  - `half-reduced` 덜 약분한 답(12/18 → 6/9): "6과 9는 3으로 한 번 더 나눌 수 있어요." → 디딤돌 나누기 줄
  - `small-num` "분자가 작으면 기약분수"(3/9를 고름): "3과 9는 둘 다 3으로 나누어떨어져요."
  - `denom-swap` 통분 때 분모만 바꿈(1/2, 3/8 → 1/8, 3/8): "분모에 4를 곱했으니 분자에도 4를 곱해요."
  - `denom-sum` 공통분모를 더하기로(1/2, 1/3 → 분모 5): "공통분모는 두 분모의 **배수**예요."
  - `bigger-denom` 분모가 크면 큰 분수(2/5 > 2/3): "통분해서 분자를 비교해 봐요. 분모가 크면 조각이 더 작아요."
  - `num-only-compare` 통분 없이 분자만 비교(3/8 vs 2/3 → 3/8이 큼): "분모가 다르면 먼저 통분해요."
  - `equal-wrong` `=`를 고름: "통분한 두 분자가 달라요. 어느 쪽이 큰지 봐요." / 정답이 `=`인데 부등호를 고름: "통분하면 두 분수가 똑같아요."
  - `concat` 분자·분모를 이어 소수로(3/5 → 0.35): "분모가 10이 되게 바꾼 뒤 분자를 소수로 읽어요."
  - `drop-zero` 100분의 한 자리 수에서 0을 빠뜨림(4/100 → 0.4): "분모가 100이면 소수 두 자리예요. 0.04로 써요."
  - `shift-place` 자리 착각(75/100 → 7.5): "100분의 75는 1보다 작아요. 0.75예요."
  - 보정 보기(오개념 식이 0 이하·겹침이라 "분자 ±1"로 채운 보기)의 힌트: "막대를 다시 보며 차근차근 세어 봐요."

## 5. ② 분모가 다른 분수의 덧셈과 뺄셈 탐험관 (`fraction_unlike.html`, key `fracunl`)

**수 규칙**: 입력 분수는 **기약분수**(대분수는 분수 부분이 기약), 두 분모는 서로 다르고 2~12, 공통분모 ≤ 24, 대분수 자연수 부분 1~4. 결과는 기약분수·대분수(분모가 다른 두 기약분수의 합·차는 자연수가 될 수 없으므로 자연수 결과는 없다). 관마다 3문제(순서 고정).

**공통 흐름(1~6관)**: 식 한 줄 → 막대(분수 부분만, 자연수는 배지) → `[통분하기]` 버튼 한 번(두 막대가 공통분모로 `resplitTo`, 식 아래에 통분한 식 한 줄이 나타남) → **3지선다(최종 답, 기약분수·대분수)** → 정답 뒤 확인 장면(합친 막대·꽉 찬 막대가 `자연수` 배지로 올라감·약분 `merge`가 자동 재생). 통분은 ①에서 익혔으니 여기서는 공통분모를 고르는 단계 없이 버튼으로 보여 준다. 1칸씩 칠하기 버튼은 없다. "약분 안 한 답"을 고르면 디딤돌 나누기 줄이 열린다(§3).

## 6. 순수 계산 모듈 (DOM 없음, 시험 대상)

### 6-1. `FracReduceCore` (`js/fraction_reduce-core.js`)
- 수 모양은 4-2 `FractionCore`와 같은 `{ w, n, d }`. 글자 표기·읽기는 **`FractionCore.token`·`label`을 불러 쓴다**(`fraction_add-core.js`를 먼저 싣는다, 그 파일은 고치지 않음).
- `gcd(a,b)`, `lcm(a,b)`.
- `isSimplest(f)`: 분수 부분 기준(`gcd(n, d) === 1`), 가분수(`n ≥ d`)는 `false`, `n === 0`은 `true`.
- `simplify(f)`: 가분수·대분수 안의 가분수(`1과 6/4`)도 받아 기약분수 대분수로(`1과 6/4` → `2와 1/2`, `6/3` → `2`, 자연수는 `{w, n:0, d:1}`).
- `reduceBy(f, k)`: k가 분자·분모를 둘 다 나누지 못하면 `throw`.
- `divideSteps(f)`: 2·3·5·7 중 나누어지는 가장 작은 수부터 나눠 가는 과정 배열(12/18 → `[{k:2, f:6/9}, {k:3, f:2/3}]`, 7/9 → `[]`). 2·3·5·7로 끝까지 못 줄이는 분수(11/22)는 `throw`(문제 생성기가 만들지 않음).
- `scale(f, k)`, `commonDenominator(d1, d2)` → `{ d, chips }`(chips = 큰 분모의 배수를 차례로, 마지막이 d: 6·8 → `[8, 16, 24]`), `toCommon(a, b)` → `{ a, b, d }`(문제 순서 유지), `compare(a, b)` → `'>'|'<'|'='`.
- `toDecimal(f)` → `{ k, scaled, places, text }`(2/5 → k 2, 4/10, 1, `'0.4'`; 1/25 → k 4, 4/100, 2, `'0.04'`; 1과 2/5 → `'1.4'`). 분모가 10·100으로 안 바뀌면 `throw`(1/3).
- `makeProblem(kind, rng)`, `wrongChoices(problem)`, `makeRound(lab, rng)`, `makeMixedRound(rng, n = 10)` — 4-2 `FractionCore`와 같은 계약에 아래를 더한다.
  - **후보 풀**: 종류마다 조건에 맞는 문제를 미리 다 늘어놓은 풀에서 `rng`로 뽑는다(무작위 재추첨 반복 금지 → 무한 루프 없음). 풀이 작은 종류(`to-decimal-10` 등)는 한 판 안에서만 중복을 막고 판 사이 중복은 허용한다.
  - **중복 키**: 두 수의 순서만 바뀐 문제는 같은 문제로 본다(덧셈·비교·통분). 뺄셈은 순서가 뜻이 있어 다른 문제.
  - **오답 보기**: 정답·서로와 `token`이 겹치거나, 0 이하이거나, 분모 0이면 버리고 보정 보기로 채운다. 각 보기에 `mistake`. 판별형은 오답이 정답 조건을 만족하면 안 된다: `reduce-which` 오답은 공약수가 아님, `simplest-pick` 오답은 기약분수가 아님, 비교는 기호 3개 고정.
- `LAB_KINDS`: 1관 `equiv-split, equiv-up, equiv-up` · 2관 `reduce-by-2, reduce-by-3, reduce-which` · 3관 `simplest-1, simplest-2, simplest-pick` · 4관 `common-multiple, common-coprime, common-lcm` · 5관 `compare-same-num, compare-unlike, compare-unlike` · 6관 `to-decimal-10, to-decimal-100, compare-decimal`. 7관 전용 `simplest-choose`(7관 섞기에서 `equiv-split`·`simplest-1/2` 자리에 대신 들어감).
- 범위 보장: `equiv-split` 쪼갠 칸 ≤ 24. `reduce-*`·`simplest-*` 처음 분수 분모 ≤ 24, 소인수 2·3·5·7만, 진분수. `reduce-which`는 분자만 또는 분모만 나누어지는 수(2~9)가 2개 이상 있는 분수만. `simplest-2`는 `divideSteps` 길이 ≥ 2. `common-*` 두 분수 기약·분모 서로 다름·공통분모 ≤ 24, `common-lcm`은 공통분모 < 두 분모의 곱이고 어느 분모도 다른 분모의 배수가 아님. `compare-*` 공통분모 ≤ 24, 10문제 섞기에서 `=` 정답이 나올 수 있게 `compare-unlike` 풀에 크기 같은 쌍(기약 아닌 쪽 하나 허용, 예 2/3 vs 8/12)을 약 1/6 섞는다. `to-decimal-*` 처음 분수 기약, 결과 소수 끝자리 0 없음.

### 6-2. `FracUnlikeCore` (`js/fraction_unlike-core.js`)
- `FractionCore`·`FracReduceCore`를 불러 쓴다(싣는 순서 `fraction_add-core` → `fraction_reduce-core` → `fraction_unlike-core`).
- `addUnlike(a, b)`, `subUnlike(a, b)`(결과 ≤ 0이면 `throw`) → `{ common: { a, b, d }, raw: 통분한 채 계산한 값(받아올림 정리한 대분수, 약분 전), split: 받아내림이면 쪼갠 빼지는 수(2와 15/12) 아니면 null, answer: 기약분수·대분수 }`. `needsCarry`·`needsBorrow`는 통분한 분자 기준.
- `makeProblem` · `wrongChoices` · `makeRound` · `makeMixedRound`: §6-1과 같은 계약(후보 풀, 중복 키, `token` 겹침 기준).
- `LAB_KINDS`: 1관 `add-proper, add-proper, add-proper-reduce` · 2관 `add-over, add-over, add-over-reduce` · 3관 `mixed-add, mixed-add, mixed-add-carry` · 4관 `sub-proper, sub-proper, sub-proper-reduce` · 5관 `mixed-sub, mixed-sub, mixed-sub-reduce` · 6관 `mixed-sub-borrow ×3`.
- 범위 보장: 입력 기약·두 분모 서로 다름·공통분모 ≤ 24. 이름에 `-reduce`가 붙은 종류만 `raw`의 분수 부분이 약분되고, 나머지 종류는 약분되지 않는다(`mixed-add-carry`·`mixed-sub-borrow` 포함). `mixed-*` 결과는 자연수 ≥ 1, 분수 부분 분자 ≥ 1. `mixed-sub-borrow`는 두 자연수의 차 ≥ 2(결과 자연수 ≥ 1), 통분한 분자가 빼는 쪽보다 작음. 약분 종류는 약분 가능한 쌍 풀에서만 뽑는다(분모를 먼저 뽑지 않음).

## 8. 검증

- **자동 시험** (노션 미접속):
  - `FracReduceCore`: `gcd`·`lcm` 표본, `isSimplest`(7/9 참, 6/9 거짓, 5/3 거짓), `simplify`(12/18 → 2/3, 9/6 → 1과 1/2, 6/3 → 2, 1과 6/4 → 2와 1/2), `reduceBy` 못 나누는 수 `throw`, `divideSteps`(12/18 두 단계, 7/9 빈 배열, 11/22 `throw`), `commonDenominator`(2·8 → 8, 3·4 → 12, 6·8 → 24, 칩 `[8, 16, 24]`), `toCommon` 순서 유지, `compare` 세 경우, `toDecimal`(2/5 → 0.4, 3/4 → 0.75, 1/25 → 0.04, 1과 2/5 → 1.4, 1/3 `throw`).
  - 종류별 seed 300개가 §6-1 범위 안. 오답 보기 2개가 정답·서로와 `token`이 겹치지 않음, 판별형 오답이 정답 조건을 만족하지 않음(`reduce-which` 오답은 공약수 아님, `simplest-pick` 오답은 기약 아님), 보정 보기에 보정 힌트가 붙음.
  - `FracUnlikeCore`: 1/2 + 1/3 = 5/6, 1/6 + 1/3 = 1/2, 5/6 + 3/4 = 1과 7/12, 3과 1/4 − 1과 2/3 = 1과 7/12(`split` = 2와 15/12), `subUnlike` 0 이하 `throw`. 종류별 seed 300개: 입력 기약, 분모 서로 다름, 공통분모 ≤ 24, `-reduce` 여부가 종류와 맞음, `mixed-*` 결과 자연수 ≥ 1·분자 ≥ 1, 답이 항상 기약분수.
  - `makeRound`·`makeMixedRound`(두 모듈): 3문제·10문제, 중복 키 기준으로 중복 없음, 한 종류 ≤ 3, `LAB_KINDS` 차례 정렬, ①의 7관 섞기에 `equiv-split`·`simplest-1/2` 없음, 5관 `compare-unlike` 2000판 중 `=` 정답이 나옴. 같은 함수를 500번 불러도 끝남(시간 제한 안).
  - 감싸개: 스크립트 순서·상대 경로·800줄 미만·`QuizChoices` 가드·`?v=` 도장(기존 시험 묶음이 새 파일도 훑는지 확인).
  - 퀴즈 자료 JSON: 12제, 보기 3개, 글자 표기 계약만, 해설에 보기 번호 없음, "가분수로 바꿔 계산"·"분모끼리 곱해 통분"·"나눗셈으로 소수 만들기" 풀이 문항 없음, 계산 정답 직접 검산.
- **화면**: 쓰기 차단 서버(`guarded_preview_server.py`, 8767)에서 375px 세로로 14개 관을 모두 한 판씩 끝까지 조작해 사진. 틀린 보기·안 나누어지는 ÷ 버튼을 일부러 눌러 노란 힌트·디딤돌 나누기 줄·🪜 버튼 확인, 24칸 막대·배수 칩 4개·쌍 보기·계단 링크가 넘치지 않는지, 데스크톱 1회.
- **작업 등급**: 화면 = L1-화면, 단원 core·`Frac5Draw` = 수학 화면 부품(L1, `kids/core/` 아님), 퀴즈 자료 = L0, **노션 CURRICULUM_DB 등록 = 운영 DB 쓰기라 사용자 승인 후** `register_curriculum.py`로만(학년 선택지 `5-1`은 이미 있음). 등록 전에는 퀴즈 탭이 "다시 불러오기"만 보여 준다(하드코딩 대체 문제 없음).
