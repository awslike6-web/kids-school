# 🎯 5분 퀘스트 3·3·3 마스터리 작업 절차 (quest-engine-spec)

> **원본 위치**: 이 파일은 `.agent/skills/quest-engine-spec/SKILL.md`가 원본입니다. `.claude/skills/`는 사본이므로 직접 고치지 마세요. 고친 뒤에는 `python scripts/sync_agent_skills.py`를 실행합니다.
>
> **사실 정보의 원본은 따로 있습니다**: 파일 위치·전역 API·메서드 표는 `kids/core/CORE_CATALOG.md` §2-2가 유일한 원본입니다. 이 스킬에는 규칙 요약과 작업 절차·함정만 둡니다. 둘이 다르면 카탈로그와 실제 코드가 맞습니다.

## 1. 먼저 읽을 것
1. `kids/core/CORE_CATALOG.md` §2-2: `quest-mastery.js`, `quest-ui-renderer.js`, `quest-runner.js`, `quest-runner-ui.js`의 역할과 API
2. `GEMINI.md` §4: 3·3·3과 기존 4+1 프레임의 적용 범위
3. `docs/notion_schemas_school.md`의 VOCA_DB 표: `숙련도`, `시험범위`, `달성`, `학년` 속성

## 2. 핵심 규칙 요약
- **적용 범위**:
  - 3·3·3 대상: 영어·국어·사회·과학의 노션 VOCA_DB 단원 중 항목이 3개 이상인 단원
  - 기존 4+1 유지: 수학, 사료/실험 퀴즈, 민서 정적 뱅크, 노션에 없는 단원
  - URL에 `?engine=classic`을 붙이면 강제로 기존 4+1이 됩니다.
- **스테이지**:
  - 개수는 `max(1, round(n/10))`입니다. `시험범위` 체크 항목을 앞 스테이지에 먼저 배치하고, 단어와 문장을 비례 배분합니다.
  - 숙련도는 노션 페이지 `id` 기준이라, 항목이 추가·삭제돼 스테이지가 다시 짜여도 진도가 유실되지 않습니다.
- **레벨**: count 0~2는 Lv.1, 3~5는 Lv.2입니다.
  - **은메달**: count 6에 도달하면 `silverDate`에 오늘 날짜를 기록하고, 그날은 더 오르지 않습니다.
  - **금메달**: 다음 날부터 6~8이 Lv.3이 되고, 9가 되면 금메달이며 노션 `달성`을 true로 바꿉니다.
  - **녹슨 왕관**: 금메달 후 `lastReviewed`로부터 2일 이상 지나면 복습 문제로 소환합니다. 틀리면 count 5로 내리고 `달성`을 false로 바꿉니다.
  - **카운트 판정**: 첫 시도에 맞혔을 때만 +1이고, 힌트를 본 뒤 맞히면 그대로입니다.
- **슬롯**:
  - 1~2번: 현재 스테이지 단어 (Lv.1이면 2번은 `match_3x3`)
  - 3번: 문장·숙어 (없으면 단어)
  - 4번: 녹슨 왕관 → 이전 스테이지 은메달 → 현재 스테이지 순서
  - 5번: 가장 높은 레벨의 승급 도전
  - Lv.3 조립은 한 판에 최대 2개입니다. 출제할 수 있는 항목이 모두 오늘 은메달이면 `isTodayAllSilver` 상태가 되어 Lv.2 복습만 냅니다.
- **에러리스**:
  - 오답에 경고음, 하트 감소, 빨간 X가 없고 격려 음성 `fairyEncourage`만 냅니다.
  - 틀린 블록은 슬롯에 넣지 않고, 정답 블록에 노란 테두리와 흔들림을 줍니다.
  - 문장 조립은 최대 5조각으로 묶고, `...`가 들어간 패턴 항목은 "뜻 보고 표현 고르기"로 대신 출제합니다.
- **동기화**:
  - **Pull**: 단원을 불러올 때 노션 값과 병합합니다. 아직 보내지 않은 로컬 진도와 10분 안에 보낸 로컬 진도만 높은 값으로 보호하고, 그 외에는 노션 값을 기준으로 삼습니다. 그래야 다른 기기에서의 강등이 반영됩니다.
  - **Push**: 5문제를 다 풀면 변경분과 이전 실패분을 한 번에 최대 10건까지 비동기로 PATCH합니다. 실패분은 localStorage 대기열에 남겨 다음 판에 다시 보냅니다.
- **보존할 기존 호출**: 완주 보상 `grantRewardAndShowUI(3, true)`, 학습일지 `sendStudyLogToNotion`, 가디언 계측 `StudyActivity.setPhase`/`recordCorrect`는 가디언 앱과 윈도우 제어기가 의존하므로 시그니처를 바꾸지 않습니다.

## 3. 작업 절차
1. 코드를 고치기 전에 ASDST 계획을 보고합니다. 노션 스키마나 동기화 로직 변경은 패스트트랙 대상이 아니므로 반드시 승인을 받습니다.
2. 엔진(`quest-mastery.js`)은 DOM을 만지지 않게 유지합니다. 화면은 `quest-ui-renderer.js`, 흐름은 `quest-runner.js`에서 다룹니다. 각 파일은 800줄 미만이어야 합니다.
3. **단위 검증**: 정적 서버를 띄우고 `scripts/verify_quest_mastery.html`을 열어 전부 PASS인지 확인합니다. 규칙을 바꿨으면 `scripts/verify_quest_mastery.js`에 케이스를 추가합니다.
4. **화면 검증**: 아래 두 주소를 폰 너비(375px)에서 확인합니다.
   - `quest_runner.html?subject=english&user=minsu&unit=L9` (마스터리)
   - `quest_runner.html?subject=math&user=minsu` (기존 4+1)
   - 운영 DB 보호를 위해 노션 쓰기를 가로챈 상태에서 한 판을 끝까지 풀고, 숙련도 PATCH·보상 PATCH·학습일지 POST가 호출되는지 봅니다.
5. **실제 노션 쓰기 시험**은 사용자 승인 후 1건만 합니다. `updateVocaMasteryProgress`로 쓰고, 페이지를 다시 읽어 확인한 다음, 원래 값(`숙련도` 빈칸, `달성` 원래 값)으로 되돌리고 한 번 더 읽어 확인합니다.
6. **문서 동기화**: `CORE_CATALOG.md`, `docs/english_spec.md`(또는 해당 과목 spec), 스키마 문서를 갱신하고, 이 스킬을 고쳤다면 `python scripts/sync_agent_skills.py --check`가 통과해야 합니다.
7. 커밋·푸시 후 `log_dev_timeline.py`로 개발 타임라인에 기록합니다(master-tower `GEMINI.md` 절차).

## 4. 함정 (실제로 막혔던 것들)
- **이 PC에는 Node가 없습니다**: JS 검증은 브라우저로 합니다. 브라우저가 옛 스크립트를 캐시하므로, 다시 열기 전에 `fetch(url, {cache:'reload'})`로 갱신하거나 주소에 쿼리를 붙입니다.
- **가디언 계측은 실제 터치만 셉니다**: `StudyActivity.recordCorrect`는 5초 안에 `event.isTrusted === true`인 입력이 있어야 정답을 셉니다. JS `.click()`으로 푼 문제는 0으로 나오는 게 정상이고, 계측을 확인하려면 실제 클릭으로 시험합니다.
- **관리자 모드에서는 노션에 안 씁니다**: `localStorage.currentUserName`이 `아빠`/`엄마`/`어른`이면 `updateVocaMasteryProgress`가 PATCH를 건너뛰고 true를 반환합니다. 실제 쓰기 시험 전에 확인합니다.
- **배포된 Worker는 저장소 코드보다 옛 버전입니다**:
  - `Pragma: no-cache` 헤더는 CORS에서 막히고, `?force=true`는 노션까지 넘어가 400이 납니다. 숙련도 조회는 기본 요청으로 하고, 엣지 캐시(최대 5분) 지연은 10분 보호 규칙이 흡수합니다.
  - Worker를 재배포하면 이 함정이 바뀌므로 이 문단도 함께 고칩니다.
- **날짜는 로컬 기준입니다**: `silverDate`와 `lastReviewed`는 로컬 `YYYY-MM-DD`입니다. 기존 VOCA 캐시 키의 `toISOString()`은 UTC라서 한국 시간 오전 9시 전에는 "어제"가 되니, 같은 방식으로 날짜를 만들지 않습니다.
- **번호로만 맞추는 단원은 학기가 섞입니다**: 과학 `3`은 "3. 온도와 열"(5-2)과 "3-1~3-5 용해와 용액"(5-1)에 모두 걸립니다. 부모 설정의 `semester`(민수 기본값 `5-2`)로 `학년`을 거르고, 학기가 맞는 항목이 3개 미만이면 단원 전체를 씁니다. 새 단원을 등록할 때는 `학년`을 꼭 채웁니다.
- **노션에 없는 단원은 시작이 늦어질 수 있습니다**: 단원 키에 숫자가 없으면(예: `phonics`) 과목 전체 조회를 생략하고 바로 기존 4+1로 넘어갑니다. 숫자가 있으면 정확히 일치하는 단원이 없을 때 과목 전체를 한 번 더 조회합니다.
- **빈 캐시와 오프라인**: 당일 캐시가 비어 있고 노션 조회도 실패하면, 기존 4+1 경로가 빈 문제로 오류를 냅니다. 3·3·3 도입 전부터 있던 문제이며, 개발 현황판에 "5분 퀘스트 오프라인·빈 캐시 폴백 보완"으로 등록돼 있습니다.
